## 离散数学

_离散数学是研究可数、离散结构的数学，是计算机科学的基础。本文涵盖了命题逻辑与谓词逻辑、证明技巧、集合、关系、函数、图论基础以及递归关系。_

- 在前几章中，我们研究了连续数学：微积分（第3章）、概率分布（第5章）以及基于实数参数的优化问题（第6章）。但计算机本质上是**离散**的机器。它们存储比特（0或1），处理整数，遵循分支逻辑，并操作有限的数据结构。**离散数学**为描述这些结构提供了正式的语言。

- 本章中的所有内容都依赖于离散数学：处理器的逻辑门属于布尔代数，调度算法需要正确性证明，内存管理涉及集合运算，算法分析则离不开递归关系。

## 命题逻辑

- **命题逻辑**是关于真/假陈述的代数。**命题**是指要么为真（T）、要么为假（F）的陈述，不可能同时为真和假。“正在下雨”是一个命题；“现在几点了？”不是命题（它是一个问题，而非具有真值的陈述）。

- 命题可以通过**逻辑联结词**组合而成：

- **AND**（合取，$p \wedge q$）：仅当$p$和$q$都为真时结果为真。
- **OR**（析取，$p \vee q$）：当$p$或$q$至少有一个为真时结果为真。
- **NOT**（否定，$\neg p$）：翻转真值。
- **IMPLIES**（蕴含，$p \to q$）：仅当$p$为真而$q$为假时结果为假。“如果下雨，地面就会湿”只有在下雨但地面干燥时才不成立。
- **IFF**（双条件，$p \leftrightarrow q$）：当两者真值相同时结果为真。

- **真值表**会详尽列出所有可能的输入组合及其对应的输出。对于$n$个命题，表中共有$2^n$行。我们通过真值表来验证逻辑等价性：

| $p$ | $q$ | $p \wedge q$ | $p \vee q$ | $p \to q$ |
| ----- || ----- || -------------- || ------------ || ----------- ||
| T | T | T | T | T |
| T | F | F | T | F |
| F | T | F | T | T |
| F | F | F | F | T |

- 其中$p$为假时的蕴含行值得注意：$F \to q$无论$q$为何值都为真。这就是**空洞真理**。“如果猪会飞，那我就是英格兰国王”在逻辑上为真，因为前提为假。这看似违反直觉，但对数学推理而言至关重要。

- **逻辑等价式**是指在所有真值下都成立的恒等式：

- **德摩根定律**：$\neg(p \wedge q) \equiv \neg p \vee \neg q$以及$\neg(p \vee q) \equiv \neg p \wedge \neg q$。要对合取式取反，需分别取反各部分并将联结词换成析取（反之亦然）。这些规则在编程中直接体现：`!(a && b)`等价于`(!a || !b)`。

- **逆否命题**：$p \to q \equiv \neg q \to \neg p$。“如果下雨，地面就会湿”等价于“如果地面不湿，就没下雨”。这是一种强大的证明技巧。

- **双重否定**：$\neg(\neg p) \equiv p$。

- **分配律**：$p \wedge (q \vee r) \equiv (p \wedge q) \vee (p \wedge r)$。

- 在所有真值赋值下都恒为真的公式称为**重言式**；恒为假的称为**矛盾式**；有时为真、有时为假则称**偶然式**。例如，$p \vee \neg p$是重言式，而$p \wedge \neg p$是矛盾式。

## 谓词逻辑与量词

- 命题逻辑无法表达关于集合中_所有_或_某些_元素的陈述。“大于2的素数都是奇数”这类陈述需要用到**谓词逻辑**，它在命题逻辑的基础上引入了变量、谓词和量词。

- **谓词**是指依赖于变量的陈述：$P(x)$表示“$x$是偶数”。当给$x$赋予具体值时，它便成为命题：如$P(4)$为真，$P(7)$为假。

- **量词**用于表达范围：

- **全称量词**（$\forall$）：“对所有……而言”。$\forall x \, P(x)$意为“对定义域中的任意$x$，$P(x)$都为真”。
- **存在量词**（$\exists$）：“存在……”。$\exists x \, P(x)$意为“至少存在一个$x$，使得$P(x)$为真”。

- 对量词取反会使其互换：$\neg(\forall x \, P(x)) \equiv \exists x \, \neg P(x)$。“并非所有人都及格”意味着“有人不及格”。同理，$\neg(\exists x \, P(x)) \equiv \forall x \, \neg P(x)$。“不存在完美的算法”意味着“每种算法都有缺陷”。

- 嵌套量词可以表达复杂的关系。$\forall x \, \exists y \, (y > x)$意为“对任意一个数，都存在比它更大的数”（对整数而言成立）。量词的顺序很重要：$\exists y \, \forall x \, (y > x)$意为“存在一个数，它比所有其他数都大”（对整数而言不成立）。

- 谓词逻辑是形式化规范的语言。当我们说某个算法“正确”时，意指$\forall \text{输入} \, x, \, \text{输出}(x) = \text{期望结果}(x)$；当我们说它“终止”时，意指$\forall x \, \exists t \, \text{停机}(x, t)$。

## 证明技巧

- **证明**是一种能确凿证明某个陈述为真的逻辑论证。与仅凭经验证据（仅说明某事物在已测试案例中有效）不同，证明能保证它对所有情况都成立。这是计算机科学中的正确性标准。

- **直接证明**：假设前提成立，通过逻辑步骤推导出结论。要证明“若$n$为偶数，则$n^2$也为偶数”：假设$n = 2k$（其中$k$为整数），则$n^2 = 4k^2 = 2(2k^2)$，显然为偶数。

- **反证法**：假设该陈述为假，进而导出矛盾。要证明$\sqrt{2}$是无理数：假设$\sqrt{2} = a/b$（且$a/b$已化为最简分数）。于是有$2 = a^2/b^2$，即$a^2 = 2b^2$，说明$a^2$为偶数，故$a$也为偶数，设$a = 2c$。代入得$4c^2 = 2b^2$，即$b^2 = 2c^2$，说明$b$也是偶数。但这与“$a/b$为最简分数”的假设矛盾。
- **归纳证明**：通过以下步骤证明某个命题对所有自然数成立：(1) 验证**基例**成立（通常为 $n = 0$ 或 $n = 1$）；(2) **归纳步骤**：若该命题对 $n = k$ 成立（归纳假设），则它对 $n = k + 1$ 也成立。

- 例如，证明 $\sum_{i=1}^{n} i = \frac{n(n+1)}{2}$：
- 基例：$n = 1$ 时，$1 = \frac{1 \cdot 2}{2} = 1$，成立。
- 归纳步骤：假设 $\sum_{i=1}^{k} i = \frac{k(k+1)}{2}$。那么 $\sum_{i=1}^{k+1} i = \frac{k(k+1)}{2} + (k+1) = \frac{k(k+1) + 2(k+1)}{2} = \frac{(k+1)(k+2)}{2}$，这正是 $n = k+1$ 时的公式。证明完毕。

- 归纳法是证明递归算法和数据结构性质的重要工具。每个递归算法都隐含着对其正确性的归纳证明：基例对应终止条件，归纳步骤对应递归调用。

- **强归纳法**假设该命题对直到 $k$ 的所有值都成立（而不仅仅是 $k$），然后证明它对 $k + 1$ 也成立。当递归依赖于多个先前值时，强归纳法尤为有用。

- **鸽巢原理**：如果把 $n+1$ 个物体放入 $n$ 个盒子中，那么至少有一个盒子会包含至少两个物体。该原理简单却极为强大。它可用来证明：任意13个人中至少有两人生日月份相同；在网络领域，它说明当元素数量超过桶的数量时，哈希冲突是不可避免的。

## 集合

- **集合**是由互不相同的元素组成无序的集合。集合是数学中最基础的数据结构，从类型系统到数据库查询都离不开它。

- **集合运算**（与第5章概率论中的内容相关）：

- **并集** $A \cup B$：属于 $A$ 或 $B$ 或两者都有的元素。
- **交集** $A \cap B$：同时属于 $A$ 和 $B$ 的元素。
- **补集** $\bar{A}$：不属于 $A$ 的元素（相对于全集而言）。
- **差集** $A \setminus B$：属于 $A$ 但不属于 $B$ 的元素。
- **笛卡尔积** $A \times B$：所有有序对 $(a, b)$，其中 $a \in A$，$b \in B$。

- **幂集** $\mathcal{P}(A)$ 是 $A$ 的所有子集构成的集合。若 $|A| = n$，则 $|\mathcal{P}(A)| = 2^n$。对于 $A = \{1, 2\}$，有 $\mathcal{P}(A) = \{\emptyset, \{1\}, \{2\}, \{1, 2\}\}$。

- **基数**用于衡量集合的大小。有限集合的基数为整数；无限集合则有不同的“大小”：自然数 $\mathbb{N}$ 和有理数 $\mathbb{Q}$ 是**可数无穷**的（可以一一列举），而实数 $\mathbb{R}$ 是**不可数无穷**的（无法一一列举，由康托尔的对角线论证证明）。这一区别在计算理论中意义重大：不可计算的函数数量远远多于可计算的函数数量，因此大多数函数无法被计算。

## 关系

- 集合 $A$ 上的**关系** $R$ 是 $A \times A$ 的子集，即一组规定哪些元素之间存在关联的有序对。例如，整数上的 $\leq$ 关系就是集合 $\{(a, b) : a \leq b\}$。

- 关系的重要性质：

- **自反性**：每个元素都与自身相关联。即对所有 $a$，有 $a R a$。例如 $\leq$（每个数都小于等于自身）。
- **对称性**：若 $a R b$，则 $b R a$。例如“互为兄弟”。
- **反对称性**：若 $a R b$ 且 $b R a$，则 $a = b$。例如 $\leq$。
- **传递性**：若 $a R b$ 且 $b R c$，则 $a R c$。例如 $<$、$\leq$、“是祖先”。

- **等价关系**具备自反性、对称性和传递性。它将集合划分为若干**等价类**，同一类内的元素彼此相关，但与其他类的元素无关。模运算就是一种等价关系：$a \equiv b \pmod{n}$ 将整数划分为 $n$ 个等价类。编程语言中的类型等价也是一种等价关系。

- **偏序**具备自反性、反对称性和传递性。它定义了“小于等于”的结构，但某些元素之间可能无法比较。文件系统中的目录关系就是一种偏序（父子关系），但同级目录之间无法比较。若偏序中任意两个元素都可比较，则称为**全序**（如整数上的 $\leq$）。

- 偏序在并发编程中至关重要：“事件先后顺序”关系就是一种偏序。无法通过该关系确定顺序的事件属于并发事件，它们可以以任意相对顺序执行。

## 函数

- **函数** $f: A \to B$ 将 $A$（定义域）中的每个元素映射到 $B$（值域）中的唯一元素。函数是确定性计算的数学模型：给定输入，有且只有一个输出。

- **单射**（一对一）：不同的输入总是产生不同的输出。即 $f(a) = f(b) \implies a = b$。无损压缩属于单射：不同的输入必须压缩成不同的输出（否则无法唯一解压）。

- **满射**（映上）： $B$ 中的每个元素都能被 $A$ 中的某个元素映射到。此时值域等于值域。如果字符串数量少于可能的哈希值数量，那么将字符串映射为256位哈希值的哈希函数就不是满射。

- **双射**：既是单射又是满射。它建立了 $A$ 与 $B$ 之间的一一对应关系。双射存在逆函数。加密必须是双射：每个明文对应唯一的密文，解密函数即为逆函数。

- **复合** $(g \circ f)(x) = g(f(x))$：先应用 $f$，再应用 $g$。函数复合满足结合律（第2章提到矩阵乘法也满足结合律）。软件中的流水线就是函数复合：数据依次经过一系列变换。

## 图论基础

- 我们在第12章（图神经网络）中详细介绍了图的相关内容，包括邻接矩阵、图的类型、拉普拉斯矩阵以及谱理论。此处我们重点讨论与计算机科学相关的**算法**和**结构**特性。
- **树**是一种没有环的连通图。等价地说，它有$n$个节点和$n-1$条边。树是文件系统、XML/HTML文档、决策过程以及递归分解的结构。**有根树**有一个指定的根节点；其他每个节点恰好有一个父节点。

- 图$G$的**生成树**是一棵包含$G$中所有节点且使用其部分边的树。**最小生成树（MST）**能使总边权最小。Kruskal算法（对边排序，贪心地添加不会形成环的最轻边）和Prim算法（从起始节点开始扩展树，总是添加通往新节点的最轻边）都可以在$O(|E| \log |V|)$时间内求出MST。

- **平面性**：如果一张图能在平面上绘制且不存在边交叉现象，则它是平面图。根据**欧拉公式**，对于连通平面图有：$|V| - |E| + |F| = 2$，其中$|F|$表示面数（包括外部面）。这意味着平面图满足$|E| \leq 3|V| - 6$，因此平面图是稀疏图。电路板布线与地图着色都利用了平面性。

- **图着色**是为节点分配颜色，使得任意相邻节点颜色不同。所需的最少颜色数称为**色数**$\chi(G)$。**四色定理**指出：任何平面图的$\chi(G) \leq 4$。在计算机科学中，图着色用于寄存器分配（将变量分配到CPU寄存器中，使同时活跃的变量使用不同寄存器）以及任务调度（将任务分配到时间槽中，避免冲突任务重叠）。

- **欧拉路径**会恰好经过每条边一次。当且仅当图中恰好有0个或2个度数为奇数的节点时，欧拉路径才存在。**哈密顿路径**会恰好经过每个节点一次。判断是否存在哈密顿路径属于NP完全问题——这是计算机科学中的经典难题之一。这种对比（欧拉路径：多项式时间可解；哈密顿路径：NP完全）说明了看似相似的问题可能具有截然不同的计算复杂度。

## 递推关系

- **递推关系**用于定义这样一个序列：每一项都依赖于前几项。它们自然产生于递归算法中。

- 最简单的例子：$T(n) = T(n-1) + 1$，且$T(0) = 0$。展开后可得：$T(n) = T(n-1) + 1 = T(n-2) + 2 = \cdots = n$。其时间复杂度为$O(n)$，即简单循环的时间复杂度。

- **归并排序**对应的递推式为$T(n) = 2T(n/2) + O(n)$：将数组一分为二（得到两个规模为$n/2$的子问题），递归地对每一半排序，然后合并（需$O(n)$时间）。其解为$T(n) = O(n \log n)$。

- **主定理**用于求解形如$T(n) = aT(n/b) + O(n^d)$的递推式：
- 若$d > \log_b a$，则$T(n) = O(n^d)$（每层的工作量占主导）；
- 若$d = \log_b a$，则$T(n) = O(n^d \log n)$（各层工作量平衡）；
- 若$d < \log_b a$，则$T(n) = O(n^{\log_b a})$（子问题数量占主导）。

- 对于归并排序：$a = 2, b = 2, d = 1$。由于$d = \log_2 2 = 1$，属于平衡情况，故$T(n) = O(n \log n)$。

- **斐波那契递推式**为$F(n) = F(n-1) + F(n-2)$，且$F(0) = 0, F(1) = 1$，其闭式解为$F(n) = \frac{\phi^n - \psi^n}{\sqrt{5}}$，其中$\phi = \frac{1+\sqrt{5}}{2}$（黄金比例），$\psi = \frac{1-\sqrt{5}}{2}$。这表明斐波那契数列呈指数级增长，复杂度为$O(\phi^n)$，因此简单的递归实现斐波那契数列会极其缓慢。

- **组合数学**（排列、组合、二项式定理及容斥原理）将在第5章（概率）中介绍。这些计数技术对算法分析至关重要（例如可能的输入数量、比较次数等），此处不再赘述。

## 可计算性

- 并非所有问题都能被计算。这是数学中最深刻的结论之一，它划定了计算机能力的基本界限。

- **图灵机**是一种抽象的计算模型：由无限长的磁带（每个单元格存储一个符号）、读写头以及有限状态集和转移规则组成。尽管结构简单，但图灵机能够计算任何真实计算机能计算的内容。这就是**丘奇-图灵论题**：任何可有效计算的函数都能被图灵机计算。

- 每种编程语言（Python、C、Haskell）都是**图灵完备**的：它们可以模拟图灵机，从而计算一切可计算的东西。语言之间的差异仅在于便利性、速度和安全性，而不在于它们能计算的内容本身。

- **停机问题**询问：给定一个程序和输入，该程序最终会停止还是会永远运行？图灵于1936年证明：不存在能普遍解决此问题的算法。证明采用反证法：假设存在一个停机检测器$H(P, x)$。构造程序$D$，使其运行$H(D, D)$并与$H$的结论相反。若$H$判定$D$会停机，则$D$会进入无限循环；若$H$判定$D$会循环，则$D$会停机。由此产生矛盾。

- 这不是当前技术的限制，而是数学上的不可能。无论计算能力、聪明才智或人工智能发展到何种程度，都无法普遍解决停机问题。它相当于计算机科学中的哥德尔不完备定理。

- 实际影响：无法编写完美的死锁检测器、完美的病毒扫描器或完美的优化编译器。这些工具都需要普遍解决停机问题（或等价的不可判定问题）。现实中的工具只能使用启发式和近似方法，在常见情况下有效，但无法保证对所有输入都正确。

- 若存在一种总能终止并给出正确“是/否”答案的算法，则该问题是**可判定的**；若不存在这样的算法，则问题是**不可判定的**。停机问题是不可判定的。素数测试是可判定的。大多数编程语言中的类型检查也是可判定的（这是设计使然）。

## 复杂性理论

- 即使是在可计算的问题中，有些问题也比其他问题难得多。**复杂性理论**根据输入规模增大时解决问题所需的资源（时间、空间）来对问题进行分类。

![P、NP和NP完全问题：P包含于NP，NP完全问题位于边界，而P是否等于NP是核心的未解难题](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/p_np_complexity.svg)

- **P**（多项式时间）：能在$O(n^k)$时间内解决的问题，其中$k$为某个常数。例如排序（$O(n \log n)$）、最短路径（$O(|V|^2)$）、矩阵乘法（$O(n^3)$）。这些问题被视为“高效”或“易处理”的。

- **NP**（非确定性多项式时间）：指那些能在多项式时间内验证其解的问题，即便找到该解可能需要指数级时间。例如，给定一个所谓的哈密顿路径，只需检查每条边即可在$O(n)$时间内验证它；但要找到这样的路径可能需要尝试指数级多的可能性。

- 所有属于P的问题也属于NP（如果能快速求解，自然也能快速验证解）。核心问题是$P = NP$是否成立：即所有能快速验证解的问题是否也能快速求解？这是计算机科学中最重要的未解难题，克莱数学研究所为此设立了100万美元的千禧年大奖。

- 大多数专家认为$P \neq NP$，也就是说有些问题本质上比验证它们更难求解。如果$P = NP$，密码学将会崩溃（破解加密算法属于NP问题），优化、调度以及药物设计也将变得轻而易举。

- **NP完全**问题是NP中最难的问题。一个问题是NP完全的，当且仅当：(1) 它属于NP；(2) 其他所有NP问题都可以在多项式时间内被归约到它。如果你能高效解决任意一个NP完全问题，就能解决所有这类问题（从而得出$P = NP$）。

- **归约**是将一个问题转化为另一个问题的过程。如果问题A可归约为问题B，那么B至少与A一样难。库克（1971年）证明了**SAT**（布尔可满足性问题：给定一个逻辑公式，是否存在使之为真的变量赋值？）是NP完全的。卡普（1972年）通过将SAT归约到其他21个经典问题，证明了它们也是NP完全的。

- 著名的NP完全问题包括：
- **旅行商问题（TSP）**：寻找一条恰好访问每个城市一次的最短路线。
- **图着色问题**：用$k$种颜色给节点着色，使得相邻节点颜色不同（$k \geq 3$）。
- **子集和问题**：给定一组整数，是否存在一个子集其和等于目标值？
- **布尔可满足性问题（SAT）**：是否存在使逻辑公式为真的真值赋值？
- **哈密顿路径**（上文在图论中已提及）。

- 在实际应用中遇到NP完全问题时，对于大规模输入通常不会寻求精确解。相反，人们会使用：**近似算法**（找到在最优解一定范围内的解）、**启发式方法**（贪心算法、局部搜索、模拟退火等）或**特殊情形求解器**（许多NP完全问题在受限输入下容易求解）。例如，现代SAT求解器能够轻松处理包含数百万个变量的实例，尽管最坏情况下的复杂度是指数级的，但它们利用了实际实例中的结构特性。

- **NP困难**问题至少与NP完全问题一样难，但可能不属于NP（其解甚至无法在多项式时间内验证）。NP完全问题的优化版本通常属于NP困难：“寻找最短的TSP路径”是NP困难的，而“是否存在长度小于$k$的TSP路径？”则属于NP完全问题。

```python
def truth_table(n_vars, expr_fn):
    """Generate truth table for a boolean function of n_vars variables."""
    headers = [f"p{i}" for i in range(n_vars)]
    print(" | ".join(headers + ["result"]))

    for vals in itertools.product([False, True], repeat=n_vars):
        result = expr_fn(*vals)
        row = [str(v)[0] for v in vals] + [str(result)[0]]
        print(" | ".join(f"{r:>2}" for r in row))

# De Morgan's law: NOT(p AND q) == (NOT p) OR (NOT q)

truth_table(2, lambda p, q: (not (p and q)) == ((not p) or (not q)))
```

```python
def merge_sort_ops(n):
    """Count comparisons in merge sort (recurrence: T(n) = 2T(n/2) + n)."""
```

## 计算机体系结构

_计算机体系结构是指我们构建用于执行指令的机器的方式。本文涵盖了数制、逻辑门、CPU设计、指令集架构、流水线技术、存储层次结构以及虚拟内存等内容——这些是所有程序、框架和AI模型最终运行的硬件基础。_

- 每个神经网络、每个训练循环、每次推理调用，最终都会转化为流经晶体管的电信号序列。对于严肃的机器学习从业者而言，理解硬件并非可有可无：它能解释为何矩阵乘法如此快速、为何内存会成为瓶颈、为何GPU在AI训练中占据主导地位，以及为何缓存友好的代码比普通代码快100倍。

## 数制

- 计算机将所有数据表示为**二进制**（基数为2）：即由0和1组成的序列。每一位称为一个**比特**。8个比特构成一个**字节**。二进制数$b_{n-1} b_{n-2} \ldots b_1 b_0$的值为$\sum_{i=0}^{n-1} b_i \cdot 2^i$。

- 例如，$1011_2 = 1 \cdot 8 + 0 \cdot 4 + 1 \cdot 2 + 1 \cdot 1 = 11_{10}$。

- **十六进制**（基数为16）是二进制的紧凑表示方式。每个十六进制数字对应4个比特：$0\text{-}9$对应$0000\text{-}1001$，而$A\text{-}F$对应$1010\text{-}1111$。因此，$\text{0xFF} = 1111\,1111_2 = 255_{10}$。内存地址和颜色代码通常用十六进制表示。

- **补码**用于表示有符号整数。对于一个$n$位的数，最高位的权重为$-2^{n-1}$而非$+2^{n-1}$。8位补码的取值范围从$-128$到$+127$。取负数时只需翻转所有比特后再加1。这种表示方式使得加法和减法可以使用相同的硬件电路，因此它被广泛应用。

- **IEEE 754浮点数**将实数表示为$(-1)^s \times 1.m \times 2^{e-\text{bias}}$，其中$s$为符号位，$m$为尾数（小数部分），$e$为经过偏移处理的指数。

![IEEE 754 float32布局：1个符号位、8个指数位、23个尾数位](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/ieee754_float.svg)

- **float32**（单精度）：1个符号位 + 8个指数位 + 23个尾数位 = 32位。取值范围约为$\pm 3.4 \times 10^{38}$，精度约为7位十进制数字。
- **float64**（双精度）：1个符号位 + 11个指数位 + 52个尾数位 = 64位。取值范围约为$\pm 1.8 \times 10^{308}$，精度约为15位十进制数字。
- **float16**（半精度）：1 + 5 + 10 = 16位。虽然范围和精度有限，但占用的内存和带宽仅为一半。它在机器学习训练中广泛应用（混合精度，见第6章）。
- **bfloat16**：1 + 8 + 7 = 16位。其指数范围与float32相同，但精度较低。它由谷歌专门为机器学习设计：完整的指数范围可防止训练过程中出现溢出，而较低的精度对梯度更新来说也足够。

- 浮点运算**并非精确**。在float64中，$0.1 + 0.2 \neq 0.3$（实际结果为$0.30000000000000004$）。这是因为$0.1$没有精确的二进制表示，正如$1/3$没有精确的十进制表示一样。在数百万次运算中累积这些误差（如梯度下降过程）可能导致数值不稳定，因此才有了损失缩放（第6章）和卡亨求和等技术。

## 逻辑门

- 所有计算最终都归结为**逻辑门**：即实现布尔运算的物理电路（即第1节中提到的命题逻辑）。

- 基本逻辑门包括：
- **与门**：仅当两个输入均为1时，输出才为1。
- **或门**：只要有一个输入为1，输出即为1。
- **非门**（反相器）：翻转输入值。
- **与非门**：属于通用门。其他任何逻辑门都可以仅用与非门来构建。正因如此，与非门成为数字电路的基本构件。
- **异或门**：当两个输入不同时，输出为1。它在加法（二进制加法中的和位由异或门产生）和密码学中至关重要。

- **半加器**利用异或门（得到和）与与门（得到进位）来对两个单比特数进行相加。**全加器**则能对两个比特数以及一个进位输入进行相加，多个全加器串联可构成$n$位加法器。这就是CPU执行整数加法的方式：由一系列简单的逻辑门级联而成。

- **多路复用器**（MUX）根据控制信号从多个输入中选择一个。若有$n$个控制位，则可从$2^n$个输入中进行选择。多路复用器相当于硬件中的if-else语句链，广泛用于CPU数据通路中以路由数据。

- 现代处理器包含数十亿个晶体管，每个晶体管都充当微小的开关。晶体管要么处于导通状态（代表1），要么处于截止状态（代表0）。逻辑门由晶体管构成，加法器由逻辑门构成，算术逻辑单元由加法器构成，而CPU则由算术逻辑单元构成。整个计算体系都建立在这一基础之上。

## CPU体系结构

- **中央处理器（CPU）**负责执行指令。其核心组件包括：

- **算术逻辑单元（ALU）**：执行整数运算（加、减、乘）和逻辑运算（与、或、异或、移位）。实际的计算工作在此完成，它由上述逻辑门构成。

- **寄存器**：CPU内部极小且速度极快的存储单元。现代CPU拥有数十个通用寄存器，每个寄存器可存放一个字（64位CPU中为64位）。寄存器是系统中最快的内存：访问时间约为0.3纳秒。

- **程序计数器（PC）**：保存下一条待执行指令的内存地址。

- **控制单元**：解码指令并协调数据通路，告诉ALU应执行何种操作以及使用哪些寄存器。

- **指令周期**（取指-解码-执行）每秒重复数十亿次：

1. **取指**：从PC所指的内存地址读取指令。
2. **解码**：确定指令的功能（加法？从内存加载？跳转？）以及所使用的操作数。
3. **执行**：执行相应操作（ALU计算、内存访问或跳转）。
4. 更新PC（除非该指令是跳转/分支指令）。

- 运行在4 GHz频率下的CPU每秒可执行40亿个周期。每个周期耗时0.25纳秒。在此期间，光可以传播约7.5厘米，因此物理芯片尺寸至关重要：信号无法在一个周期内穿越大型芯片。

## 指令集架构

- **指令集架构（ISA）**是硬件与软件之间的约定：它定义了CPU能理解的指令、寄存器组、内存模型以及编码格式。

- **CISC**（复杂指令集计算机）：指令可能较为复杂且长度可变，并能直接访问内存。一条指令即可完成两个内存值的相乘并存储结果。**x86**（英特尔/AMD）是主流的CISC指令集，广泛应用于大多数台式机和服务器。其向后兼容性（现代x86 CPU仍能运行20世纪80年代的代码）既是优势也是负担。

- **RISC**（精简指令集计算机）：指令简单、长度固定，且仅在寄存器上操作。访问内存需要单独的加载/存储指令。更简单的指令有助于实现更高的时钟频率和更顺畅的流水线处理。

- **ARM**：移动设备领域占主导地位的RISC指令集，如今在服务器和笔记本电脑中应用也日益广泛（苹果M系列芯片采用ARM架构）。ARM的能效优势使其非常适合电池供电且散热受限的设备。
- **RISC-V**：一种开源的RISC指令集。任何人都可以无需支付许可费即可设计RISC-V芯片。它在嵌入式系统、科研以及人工智能加速器领域的应用正在不断扩大。

- CISC与RISC之间的界限已变得模糊：现代x86 CPU内部会将复杂的CISC指令解码为更简单的微操作（本质上相当于内部采用RISC），从而兼得两者的优势。

## 流水线技术

- 没有流水线技术时，CPU必须完全执行完一条指令后才能开始下一条指令。这会浪费硬件资源：当算术逻辑单元正在执行时，取指和解码单元处于空闲状态。

![CPU流水线：指令在取指、解码、执行、内存访问和写回阶段相互重叠](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/cpu_pipeline.svg)

- **流水线技术**使指令执行过程相互重叠，就像装配线一样。当指令1正在执行时，指令2正在解码，而指令3则正在被取指。一个五级流水线（取指、解码、执行、内存访问、写回）可同时处理5条指令。

- 吞吐量可接近每周期一条指令（尽管每条指令需要5个周期才能完成）。这与机器学习中的流水线原理相同：数据并行性使得计算与通信相互重叠（第6章）。

- **流水线冲突**是指流水线技术失效的情况：

- **数据相关冲突**：指令2需要指令1尚未产生的结果。例如“Add R1, R2, R3”之后紧跟“Sub R4, R1, R5”——第二条指令需要R1的值，而第一条指令仍在计算中。**转发机制**（绕过）通过将结果直接从某个流水线阶段传递到另一个阶段来解决此问题，无需等待写回阶段。

- **控制相关冲突**：分支指令（if-else）意味着在分支结果确定前，CPU无法确定下一条要取指的指令。**分支预测**会猜测分支走向，并提前沿预测路径取指。现代预测器的准确率超过95%，它们利用历史表和类似神经网络的模式匹配技术。一旦预测错误，将耗费约15个周期（流水线必须被清空并重新启动）。

- **结构相关冲突**：两条指令同时需要同一硬件资源（例如都需使用内存端口）。解决方法是复制资源或插入停顿。

## 存储器层次结构

- 计算机存储器存在根本性的矛盾：快速存储器昂贵且容量小，廉价存储器则速度慢且容量大。**存储器层次结构**通过利用**局部性原理**来弥补这一差距：程序往往反复访问相同的数据（时间局部性），或访问相邻的数据（空间局部性）。

![存储器层次结构金字塔：从顶部的寄存器（快速、容量小）到底部的硬盘（缓慢、容量大）](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/memory_hierarchy.svg)

- 按速度从快到慢排列的存储器层次如下：

- **寄存器**：访问时间约0.3纳秒，总容量约KB级别。位于CPU内部。
- **L1缓存**：访问时间约1纳秒，每个核心容量为32–64 KB。分为指令缓存和数据缓存。
- **L2缓存**：访问时间约4纳秒，每个核心容量为256 KB–1 MB。
- **L3缓存**：访问时间约10纳秒，多个核心共享的容量为8–64 MB。
- **RAM（DRAM）**：访问时间约50–100纳秒，容量8–512 GB。主存储器。
- **SSD**：访问时间约10–100微秒，容量256 GB–8 TB。持久性存储。
- **硬盘**：访问时间约5–10毫秒，容量1–20 TB。机械结构，随机访问速度极慢。

- 寄存器与RAM之间的速度差距约为300倍；寄存器与磁盘之间的差距更是高达约30,000,000倍。缓存层次结构掩盖了这一差距：如果CPU所需的数据存在于L1缓存中（即**缓存命中**），访问速度就很快；否则（**缓存未命中**），CPU必须暂停，等待从更慢的层级读取数据。

- **缓存关联性**决定了内存地址在缓存中的存储位置：
- **直接映射**：每个地址只能映射到唯一的一条缓存行。结构简单但容易产生冲突。
- **全相联映射**：任何地址都可存储在任意位置。灵活性高但搜索成本高。
- **组相联映射**（$k$路）：每个地址映射到一组共$k$个位置。这是实际CPU中采用的实用折衷方案（通常为4路或8路）。

- **缓存一致性**确保所有CPU核心看到的内存视图是一致的。当核心1写入某个地址而该地址已被核心2缓存时，一致性协议（如MESI）会使核心2的副本失效或更新。这对并发编程（文件4）至关重要，也是共享内存并行编程困难的原因之一。

- 对于机器学习从业者而言，存储器层次结构解释了以下现象：
- 矩阵运算应顺序访问内存（行优先与列优先布局会影响性能）。
- 批量大小会影响性能：更大的批次能够分摊内存延迟的影响。
- 混合精度（float16/bfloat16）可使有效内存带宽翻倍，而内存带宽往往是性能瓶颈。

## 虚拟内存

- **虚拟内存**让每个进程误以为自己拥有独立且连续的大块内存空间，尽管物理RAM是有限的且被多个进程共享。

- 地址空间被划分为固定大小的**页**（通常为4 KB）。**页表**将虚拟页号映射到物理帧号。当程序访问虚拟地址0x1234时，CPU会通过查询页表将其转换为物理地址。

- **转换后备缓冲器（TLB）**是页表项的缓存。由于页表存储在RAM中（速度较慢），TLB会将最近使用的映射关系保存在高速硬件中。若发生TLB未命中，则需遍历内存中的页表，这会耗费数百个时钟周期。

- 当程序访问的页面不在物理RAM中时，就会发生**缺页异常**。操作系统会从磁盘加载该页面（即交换操作），这一过程需要数百万个时钟周期。过多的缺页异常会导致**系统颠簸**，严重拖累性能。正因如此，机器学习训练需要足够大的RAM来存放模型、优化器状态以及合理规模的批量数据。

- **页面置换算法**用于在RAM已满时决定淘汰哪个页面：
- **LRU**（最近最少使用）：淘汰最长时间未被访问的页面。在实际大多数工作负载中表现最优。硬件上通过**时钟算法**（一种带有引用位的循环列表）来近似实现。
- **FIFO**：淘汰最旧的页面。实现简单，但可能会淘汰掉频繁使用的页面。
- **最优算法**（贝拉迪算法）：淘汰将来最长时间不会被使用的页面。该算法无法实际实现（需要预知未来情况），但可作为理论上的基准。

- 虚拟内存还提供了**隔离机制**：每个进程拥有独立的虚拟地址空间。一个进程中的错误不会破坏另一个进程的内存，因为它们的虚拟地址映射到不同的物理帧。这是操作系统安全性和稳定性的基础。

## I/O、中断与DMA

- CPU需要与外部设备通信：磁盘、网卡、键盘、GPU等。这就是**I/O子系统**。

- **程序化I/O**（轮询）：CPU在循环中反复检查设备的状态寄存器，等待数据就绪。这种方式简单，但会浪费CPU周期，使其无法执行其他有用任务。

- **中断驱动的I/O**：数据就绪时，设备会发送硬件**中断**。CPU会继续正常执行，直到中断到来，随后运行**中断处理程序**（内核函数）来处理数据。这种方式比轮询高效得多，因为CPU在等待期间不会闲置。

- 中断机制的工作流程如下：

1. 设备通过硬件线路发出中断信号。
2. CPU完成当前指令后，将当前状态（寄存器、程序计数器）保存到栈中。
3. CPU在**中断向量表**中查找对应的中断处理程序地址（该表包含各类中断对应的函数指针）。
4. 处理程序在内核模式下运行，完成I/O操作后再返回。
5. CPU恢复之前保存的状态，继续被中断的程序执行。

- 这种保存/恢复模式与上下文切换（文件3）类似，只是由硬件而非定时器触发。

- **DMA**（直接内存访问）：对于大规模数据传输（如磁盘读取、网络数据包、GPU内存拷贝），让CPU逐字节复制数据效率极低。**DMA控制器**可以在设备和RAM之间直接传输数据，无需CPU参与。CPU只需设置传输参数（源地址、目标地址、大小），DMA控制器负责执行传输，完成后通知CPU。

- DMA对机器学习至关重要：当你调用`model.to('cuda')`时，数据会通过PCIe总线经DMA从系统RAM传输到GPU内存。在训练过程中，跨GPU的梯度同步利用基于DMA的RDMA（远程直接内存访问）技术，以实现高带宽、低延迟的数据传输（第6章）。

- **总线**用于连接CPU、内存和I/O设备。现代系统使用**PCIe**（外围组件互连高速）来连接高速设备（GPU、NVMe SSD、网卡）。PCIe 4.0在x16插槽上的带宽可达约32 GB/s；PCIe 5.0则将其翻倍。总线带宽常常成为GPU训练的瓶颈：GPU的计算速度可能快于数据供给速度。

- **MMIO**（内存映射I/O）：设备寄存器被映射到内存地址。CPU使用普通的加载/存储指令读写这些地址，硬件会将访问请求路由到设备而非RAM。这种方式将内存访问和I/O访问统一为同一种机制，简化了硬件和软件设计。

```python
    hits, misses = 0, 0
```

## 操作系统

_操作系统是硬件与应用程序之间的软件层，负责资源管理、提供抽象接口以及实施隔离。本文档介绍了操作系统的功能、进程、线程、CPU调度、内存管理、文件系统以及系统调用。_

- 没有操作系统的计算机就像没有厨师的厨房：食材（硬件）虽已备齐，但无人协调谁使用炉灶、餐具该放在何处，也无法防止两人同时拿到同一把刀。而**操作系统**就是那个协调者。

- 对于机器学习从业者而言，操作系统概念可以解释：为何`nvidia-smi`能显示每个进程的GPU内存使用情况，为何训练时会因“内存不足”而崩溃，为何`fork()`会复制Python进程，以及为何Docker容器能提供隔离环境。

## 操作系统的功能

- 操作系统有三项核心职责：

- **抽象**：将硬件复杂性隐藏在简洁的接口之后。程序读写“文件”时无需关心底层存储是SSD、HDD还是网络驱动器；它们分配“内存”时无需管理物理RAM芯片；它们在“CPU”上运行时也无需担心中断和缓存一致性问题。

- **资源管理**：多个程序共享CPU、内存、磁盘和网络。操作系统决定谁在何时、以何种方式使用这些资源。公平且高效的分配策略能确保系统响应迅速。

- **隔离与保护**：程序之间不应互相干扰。浏览器中的错误不应导致内核崩溃，恶意程序也不应读取其他程序的密码。操作系统利用硬件支持（特权级别、虚拟内存）来划定界限。

## 进程

- **进程**是一个正在运行的程序，它是操作系统的基本执行单位。每个进程包含：

- **代码**（程序指令，只读）。
- **数据**（全局变量、堆分配）。
- **栈**（函数调用帧、局部变量）。
- **状态**（寄存器值、程序计数器、打开的文件等）。

- **进程控制块（PCB）**是操作系统用于跟踪进程的数据结构。它存储进程ID（PID）、状态、程序计数器、寄存器内容、内存映射、打开的文件描述符以及调度优先级。当操作系统从一个进程切换到另一个进程时，会将当前进程的状态保存到其PCB中，并加载下一个进程的状态。这就是**上下文切换**。

- 上下文切换代价高昂：保存和恢复寄存器、刷新缓存以及使TLB条目失效都需要花费微秒级时间。在运行着数千个进程的系统上，这种开销可能相当显著。正因如此，基于每请求一进程的服务架构（如旧的Apache）已被基于线程或事件驱动的架构所取代。

- Unix中的**进程创建**使用`fork()`和`exec()`：

- `fork()`会创建当前进程的**副本**。子进程会获得父进程内存、文件描述符和状态的拷贝。两个进程从同一点继续执行，但`fork()`在子进程中返回0，而在父进程中返回子进程的PID。

- `exec()`会用新程序替换当前进程的代码。通常在`fork()`之后，子进程会调用`exec()`来运行不同的程序。

- 这种先fork再exec的模式十分巧妙：创建新进程（fork）和加载新程序（exec）是两个可独立定制的操作。在fork和exec之间，子进程可以重定向输入输出、更改环境变量或降低权限。

![进程状态转换：新建 → 就绪 → 运行 → 阻塞/终止，包含抢占和I/O等待](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/process_states.svg)

- **进程状态**：进程会处于以下几种状态之一：
- **运行**：当前正在某个CPU核心上执行。
- **就绪**：正在等待CPU核心（可运行但尚未被调度）。
- **阻塞**（等待）：直到某个事件发生才能继续（如I/O完成、获取锁、定时器到期）。
- **终止**：执行完毕，等待父进程收集其退出状态。

## 线程

- **线程**是进程内的轻量级执行单元。同一进程中的所有线程共享相同的代码、数据和堆，但各自拥有独立的栈和寄存器状态。

- 相比多个进程，线程的优势在于它们共享内存，因此彼此间通信速度更快（只需读写共享变量）。进程则需要依赖进程间通信机制（管道、套接字、共享内存映射），这种方式更慢且更复杂。

- 劣势在于共享内存存在风险。两个线程同时写入同一个变量会导致**竞态条件**（结果取决于哪个线程先执行）。这就引出了同步问题，相关内容将在第4节中讨论。

- **内核线程**由操作系统调度器管理。每个线程被独立地调度到CPU核心上。创建和切换内核线程涉及系统调用，其开销与进程上下文切换类似，但略低一些。

- **用户线程**（绿色线程）由用户空间的运行时库管理，操作系统无法察觉。它们创建和切换的成本更低（无需系统调用），但一个用户线程的阻塞操作会阻塞该进程中的所有线程（因为操作系统只看到一个内核线程）。

- 现代系统采用**混合模型**：将多个用户线程映射到较少数量的内核线程上（M:N线程模型）。Go语言的goroutine和Erlang的进程都是由语言运行时调度到操作系统线程上的用户级线程。

- **线程池**会预先创建一定数量的线程来等待任务。一旦有任务到来，便将其分配给空闲的线程。这样避免了为每个任务单独创建和销毁线程的开销。Web服务器、数据库引擎以及机器学习推理服务器都使用线程池。

## CPU调度

- **调度器**负责决定每个时刻哪个进程/线程在哪个CPU核心上运行。其目标是：最大化CPU利用率、最小化响应时间（针对交互式任务）、最大化吞吐量（针对批处理任务），并确保公平性。

- **先来先服务（FCFS）**：进程按到达顺序运行。该算法简单，但存在**护航效应**：一个运行时间较长的进程会阻塞其后所有较短的进程。

- **最短作业优先（SJF）**：优先运行最短的进程。该算法能确保平均等待时间最小，但需要预先知道作业长度（通常无法实现）。其抢占式版本**最短剩余时间优先（SRTF）**会在有更短的进程到来时中断正在运行的进程。

- **轮转调度（RR）**：每个进程获得固定的**时间片**（例如10毫秒），之后被抢占并移到队列末尾。该算法公平且响应迅速，但时间片大小至关重要：太小会导致过多的上下文切换，太大则会退化为FCFS。

- **优先级调度**：每个进程都有优先级，优先级较高的进程优先运行。其风险在于**饥饿现象**：如果高优先级进程不断到来，低优先级进程可能永远无法运行。**老化机制**可解决此问题：进程等待时间越长，其优先级就越高。

- **多级反馈队列（MLFQ）**：包含多个具有不同优先级和时间片的队列。新进程从最高优先级队列开始（时间片较短）。若某个进程用完了其时间片（属于CPU密集型），则会被降级到较低优先级队列（时间片较长）。交互式进程自然会留在高优先级队列中（它们在用完时间片前会因I/O操作而阻塞）。这种方式无需预先了解作业类型即可适应不同的工作负载。

- **完全公平调度器（CFS）**：即Linux系统的调度器。它维护一棵红黑树（一种平衡二叉搜索树），其中存放按“虚拟运行时间”排序的进程——即它们已消耗的CPU时间。虚拟运行时间最小的进程将下一个运行。这样就能确保随着时间的推移，每个进程都能获得公平的CPU时间分配。CFS每次调度决策的时间复杂度为$O(\log n)$。

## 内存管理

- 操作系统负责管理物理RAM，将其分配给进程，并在不再需要时回收。

- **分页**（源自文件2）将虚拟内存划分为固定大小的页，将物理内存划分为帧。页表用于映射页与帧的关系。分页消除了外部碎片（分配之间的空闲空间），因为所有页的大小都相同。

- **请求分页**仅在首次访问页面时才将其载入RAM（而非进程启动时）。这样可以节省内存：一个代码量为1GB的程序在典型运行过程中可能仅使用50MB内存，其余部分永远不会被加载。

- 当RAM已满且需要新页面时，操作系统必须**置换**一个现有页面。**页面置换算法**（LRU、FIFO、Clock，源自文件2）用于决定置换哪个页面。良好的置换算法能减少页面错误；糟糕的置换算法则会导致系统抖动。

- **分段**将内存划分为大小可变的分段（代码段、数据段、栈段、堆段），每段都有自己的基址和长度。分段提供逻辑上的组织方式，而分页则负责物理层面的管理。现代系统很少使用分段（主要用于保护目的），而是依赖分页进行内存管理。

- **堆**是动态分配内存的区域（C语言中的`malloc`/`free`，Java中的`new`，Python中则隐式处理）。操作系统为进程提供大块内存，再由**内存分配器**（如`glibc malloc`、`jemalloc`、`tcmalloc`）将这些块进一步划分为更小的分配单元。分配器的设计会影响性能：碎片化会浪费空间，线程间的竞争则会浪费时间。

## 文件系统

- **文件系统**将持久性存储设备（SSD、HDD）上的数据组织为命名文件和目录的层次结构。

- **索引节点（inode）**存储文件的元数据：大小、所有者、权限、时间戳以及指向磁盘上数据块的指针。文件名存储在目录中，目录将名称映射到inode编号。这种分离机制使得一个文件可以有多个名称（**硬链接**）指向同一个inode。

- **FAT**（文件分配表）：一种用于U盘和SD卡的简单文件系统。该表将每个簇（块）映射到文件中下一个簇，从而形成链表。它结构简单，但不支持权限管理、日志功能，对大文件的支持也较差。

- **ext4**：Linux系统的默认文件系统。它使用带有直接、间接、双重间接及三重间接指针的inode来处理任意大小的文件。它还支持**扩展区**（连续的块范围）以提高大文件的存取效率。最大文件大小为16TB，最大分区容量为1EB。

- **日志功能**可防止系统崩溃导致的数据损坏。在修改文件系统结构之前，相关更改会先写入**日志**。如果系统在操作过程中崩溃，重启时会重放日志以完成或撤销该操作。没有日志功能的话，写入过程中的崩溃可能导致文件系统处于不一致状态（例如文件的数据块已更新但其inode未更新，反之亦然）。

- 基于**B树**的文件系统（如Btrfs、ZFS）利用B树（平衡搜索树）来组织数据和元数据，从而实现高效的查找、写时复制快照以及内置的数据完整性校验。这些正是数据库索引中所使用的同一种B树。

## 系统调用与内核模式

- **系统调用**是用户程序与操作系统内核之间的接口。当程序需要执行特权操作（读取文件、分配内存、创建进程、发送网络数据包）时，就会发起系统调用。

- CPU有两种运行模式：
- **用户模式**：受限模式。程序可以执行自己的代码并访问自身的内存，但无法直接访问硬件、其他进程的内存或操作系统数据结构。
- **内核模式**：无限制模式。操作系统内核可以访问所有硬件和内存。系统调用是从用户模式进入内核模式的受控通道。
- 当程序调用 `read()` 时，会发生以下过程：

1. 程序将参数放入寄存器并触发一个**陷阱**（软件中断）。
2. CPU切换到内核模式，并跳转到系统调用处理程序。
3. 内核验证参数，执行I/O操作，并将数据复制到用户的缓冲区。
4. 内核切换回用户模式并返回结果。

- 常见的系统调用包括：`open`、`read`、`write`、`close`（文件相关），`fork`、`exec`、`wait`、`exit`（进程相关），`mmap`、`brk`（内存相关），以及`socket`、`bind`、`listen`、`accept`（网络相关）。

- **中断**是硬件信号，会迫使CPU暂停当前工作并运行中断处理程序（位于内核中）。键盘按键、网络数据包到达或定时器计时都会产生中断。其中，定时器中断尤为重要：它使得操作系统能够抢占正在运行的进程并切换至另一个进程（即抢占式多任务处理）。

## 网络基础

- 网络栈是操作系统中用于实现机器间通信的子系统。理解它有助于了解分布式训练如何同步梯度、模型服务如何处理请求，以及为什么延迟如此重要。

![TCP/IP协议栈：应用层、传输层、网络层和链路层，每层都会添加相应的头部](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/tcp_ip_layers.svg)

- **TCP/IP模型**将网络功能划分为多个层次，每一层为上一层提供抽象接口：

- **链路层**：负责在单一物理链路上进行通信（如以太网、Wi-Fi），处理MAC地址和帧。
- **网络层（IP）**：负责将数据包从源主机路由到目的主机。每台机器都有一个**IP地址**（例如IPv4中的192.168.1.1，或128位的IPv6地址）。路由器根据目的IP逐跳转发数据包。
- **传输层（TCP/UDP）**：为应用程序之间提供端到端的通信。
- **应用层**：包含HTTP、DNS、gRPC等协议，供应用程序直接使用。

- **TCP**（传输控制协议）提供可靠且有序的数据传输。它通过三次握手（SYN、SYN-ACK、ACK）建立连接，确保数据按序到达（利用序列号和确认机制），重新传输丢失的数据包，并控制发送速率以避免网络拥塞（**拥塞控制**）。其代价是延迟：握手会增加一次往返时间，重传也会造成延迟。

- **UDP**（用户数据报协议）提供不可靠且无序的数据传输。无需握手、不重传、不保证顺序。其延迟远低于TCP。适用于对速度要求高于可靠性的场景：视频流媒体、在线游戏、DNS查询。在机器学习中，某些梯度同步协议会使用基于UDP的RDMA来降低延迟。

- **套接字**是操作系统提供的网络通信接口。**套接字**是由（IP地址、端口号）标识的端点。服务器创建套接字并将其绑定到某个端口（如HTTP使用的80端口），然后监听连接请求并接受它们。客户端则创建套接字并连接到服务器的地址和端口。数据通过套接字读写，就像操作文件一样。

- **DNS**（域名系统）将人类可读的名称（如google.com）转换为IP地址（如142.250.80.46）。它是一个分布式、分层的数据库：本地机器先询问本地解析器，后者再向根服务器查询，最终由权威服务器返回对应域名的IP地址。

- **HTTP**（超文本传输协议）是网页中的请求-响应协议。客户端发送请求（方法+URL+头部+可选正文），服务器则返回响应（状态码+头部+正文）。机器学习模型服务（如TensorFlow Serving、Triton）通常将模型以HTTP或gRPC接口的形式暴露出来。

- **延迟与带宽**：延迟是指单个数据包从源到目的地所需的时间（由物理距离和网络跳数决定）；带宽则是数据传输速率（每秒传输的字节数）。高带宽但高延迟的连接（如卫星互联网）虽然能传输大量数据，但每个字节的到达时间却很长。对于分布式训练而言，**延迟**会影响同步屏障（所有GPU必须等待最慢的那个），而**带宽**则影响大型梯度张量的传输（详见第6章）。

## 虚拟化与容器

- **虚拟化**是指在同一台物理机上运行多个操作系统。**虚拟机监控程序**（如VMware、KVM、Xen）会创建**虚拟机（VM）**，每台虚拟机拥有独立的虚拟CPU、内存、磁盘和网络接口。每台虚拟机运行完整的客户操作系统，且认为自己拥有专用的硬件。

- 虚拟机提供了强大的隔离性（一台虚拟机崩溃不会影响其他虚拟机）和灵活性（可在同一台机器上同时运行Linux和Windows，或在物理主机之间迁移虚拟机）。其代价是开销：每台虚拟机都要运行完整的操作系统内核，会占用内存和CPU资源，而这些操作与主操作系统存在冗余。

![虚拟机在虚拟硬件上运行独立的客户操作系统；容器则共享主机内核，更加轻量](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/container_vs_vm.svg)

- **容器**（如Docker、Podman）提供了一种更轻量的替代方案。容器并不虚拟化整个硬件，而是共享主机操作系统内核，并利用内核特性来隔离进程：

- **命名空间**用于隔离进程可见范围：每个容器拥有独立的进程树视图（PID命名空间）、网络接口（网络命名空间）、文件系统挂载点（挂载命名空间）以及主机名（UTS命名空间）。容器内的进程无法看到其他容器中的进程。
- **cgroup**（控制组）用于限制进程可使用的资源：CPU时间、内存、磁盘I/O、网络带宽等。容器无法超出其cgroup所允许的资源上限，从而防止某个容器耗尽其他容器的资源。
- 容器在几毫秒内即可启动（无需操作系统引导），占用资源极少（共享内核），并由**Dockerfile**定义，其中指定了基础镜像、依赖项和命令。这使得环境可复现：`docker build`能在任何地方生成相同的环境。

- 对于机器学习而言，容器解决了“在我的机器上能运行”的问题。包含特定版本的CUDA、cuDNN、PyTorch和Python的训练环境会被打包成容器镜像。任何人都能在任何机器上复现完全相同的环境。云训练平台（如AWS SageMaker、GCP Vertex AI）也是通过容器来运行训练任务。

- **Kubernetes**（K8s）用于大规模容器编排：它将容器调度到集群中的机器上，重启失败的容器，根据负载情况自动扩缩容，并管理容器间的网络通信。大规模的模型服务（成千上万个模型副本处理数百万次请求）正是基于Kubernetes运行的。

## 安全基础知识

- 操作系统通过多种机制来保障安全：

- **权限控制**：每个文件都有所有者、所属组以及权限位（针对所有者、组和其他用户的读/写/执行权限）。进程以启动它的用户的身份（UID）运行，只能访问权限位允许的文件。**root**用户（UID 0）可绕过所有权限检查，因此以root身份运行十分危险。

- **权限分离**：进程仅拥有其所需的最小权限。Web服务器不需要root权限；它应以受限用户身份运行，只能读取网页文件并绑定到端口80。一旦服务器被攻破，攻击者的访问权限也仅限于该受限用户所能操作的范围。

- **沙箱机制**：限制进程在文件权限之外的行为。**seccomp**（Linux系统）限制了进程可调用的系统调用。**AppArmor**和**SELinux**则定义了强制访问控制策略。容器结合了命名空间、cgroups和seccomp来实现多层隔离。

- **地址空间布局随机化（ASLR）**：每次程序运行时，都会随机化栈、堆和库的内存位置。这增加了攻击者利用内存损坏漏洞（如缓冲区溢出）的难度，因为他们无法预测代码或数据在内存中的具体位置。

- 安全性是系统性问题：链条的强度取决于最薄弱的一环。模型服务系统需要安全的网络通信（TLS/HTTPS）、经过认证的API访问（API密钥、OAuth）、输入验证（防止恶意输入）以及隔离的执行环境（具有最小权限的容器）。

1. 模拟轮转调度算法。给定一组具有执行时间的进程，模拟调度过程并计算平均等待时间。

```python
def round_robin(processes, quantum=3):
    """Simulate round-robin scheduling.
    processes: list of (name, burst_time) tuples.
    """
    queue = [(name, burst, 0) for name, burst in processes]  # (name, remaining, wait)
    time = 0
    log = []

    while queue:
        name, remaining, waited = queue.pop(0)
        waited += (time - waited - (processes[[p[0] for p in processes].index(name)][1] - remaining))
        run_time = min(quantum, remaining)
        log.append(f"  t={time:3d}: {name} runs for {run_time} (remaining: {remaining - run_time})")
        time += run_time
        remaining -= run_time

        if remaining > 0:
            queue.append((name, remaining, time))
        else:
            log.append(f"  t={time:3d}: {name} DONE (turnaround: {time})")

    for line in log:
        print(line)

print("Round Robin (quantum=3):")
round_robin([("P1", 10), ("P2", 4), ("P3", 6)], quantum=3)
```

```python
def lru_page_replacement(pages, n_frames):
    """Simulate LRU page replacement."""
    frames = []
    faults = 0

    for page in pages:
        if page in frames:
            frames.remove(page)
            frames.append(page)  # move to most recently used
            status = "HIT "
        else:
            faults += 1
            if len(frames) >= n_frames:
                evicted = frames.pop(0)  # remove least recently used
                status = f"MISS (evict {evicted})"
            else:
                status = "MISS (cold)"
            frames.append(page)
        print(f"  Page {page}: {status}  frames={frames}")

    print(f"\nTotal faults: {faults}/{len(pages)} ({faults/len(pages):.0%})")

print("LRU with 3 frames:")

```

## 并发与并行

_并发与并行是程序能够同时处理多项任务的方式。本文件将阐述并发与并行之间的区别、同步机制、常见的并发问题、死锁现象、无锁数据结构、并行编程模型、异步编程以及规模扩展规律——这些概念是多线程服务器、分布式训练以及所有现代应用程序的基石。_

- 单个CPU核心一次只能执行一条指令。但现代系统拥有8核、64核，甚至数千核的处理器（GPU）。即便在单个核心上，我们也希望同时处理多项任务：下载文件、渲染用户界面、处理用户输入。**并发**与**并行**便是管理这些多项任务的两种策略。

## 并发与并行之别

![并发是在单个核心上交替执行任务；并行则是在多个核心上同时执行任务](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/concurrency_vs_parallelism.svg)

- **并发**侧重于对多项任务的管理。各项任务通过交替执行来取得进展：先执行任务A，再执行任务B，然后又回到任务A。在单个核心上，并发会给人一种任务同时执行的错觉，但实际上这些任务是轮流执行的，并非真正同时进行。

- **并行**则是让多项任务真正同时执行。当系统拥有$n$个核心时，就有$n$项任务可以同时运行。并行需要多个硬件执行单元来实现。

- 用比喻来说：并发就像是一名厨师轮流切菜和搅拌锅中的食物；而并行则是两名厨师同时各做一项工作。一个系统可以是并发的而非并行的（单个核心，任务交替执行），也可以是并行的而非并发的（多个核心运行互不交互的独立程序），当然也有可能两者兼具（多个核心同时执行相互关联的任务）。

- 在机器学习领域，并发体现在数据加载过程中（将数据预处理与GPU计算同步进行）；而并行则体现在分布式训练中（多个GPU同时计算梯度，详见第6章）。

## 同步机制

- 当多个线程共享数据时，**同步机制**可用于避免竞态条件。竞态条件是指程序的结果会因线程执行顺序的不可预测性而发生变化。

- 想象有两个线程都在对同一个计数器进行加1操作：`counter += 1`。实际上这包含三个步骤：(1)读取计数器值，(2)加1，(3)将新值写回计数器。如果两个线程都读取到相同的数值（比如5），然后都加1，再将结果写回6，那么计数器的最终值就会是6，而不是应有的7。这样，一次加1的操作就丢失了。

- **互斥锁**可以确保同一时间只有一个线程能够访问临界区。线程在进入临界区之前必须先获取锁，离开后再释放锁。其他试图获取该锁的线程则必须等待锁被释放后才能继续执行。

```text
lock.acquire()
counter += 1      # only one thread at a time here
lock.release()
```

- 互斥锁虽然有效，但会导致**竞争问题**：当多个线程争抢同一个锁时，它们会花费时间等待而非执行计算任务，这限制了系统的可扩展性。在极端情况下，如果所有线程都试图获取同一个锁，那么整个程序就会变成串行执行。

- **信号量**是对互斥锁的扩展。计数信号量会维护一个计数器：`wait()`操作会减少该计数器值（如果计数器变为负数则线程会被阻塞），而`signal()`操作则会增加其值。初始值为1的信号量行为类似于互斥锁；初始值为$n$的信号量则允许最多$n$个线程同时进入临界区（这种机制适用于数据库连接等资源池场景）。

- **条件变量**能让线程在特定条件满足之前保持等待状态。线程会释放锁，然后等待条件变量，一旦有其他线程满足了该条件，它就会被唤醒。这样就可以避免忙等现象（即反复在循环中检查条件，从而浪费CPU资源）。

- **监视器**则将互斥锁、条件变量以及共享数据整合为一个统一的抽象结构。Java中的`synchronized`关键字以及Python中的`threading.Condition`类都实现了类似监视器的功能。

- **读写锁**能够区分读取者和写入者——读取者可以共享访问权，因为读取操作不会修改数据；而写入者则需要独占访问权。多个读取者可以同时持有锁，但写入者会阻塞所有的读取者和其他写入者。当读取操作的数量远远超过写入操作时，这种机制最为合适（例如用于提供预测结果的缓存模型）。

## 典型的并发问题

- **生产者-消费者问题**（带有限制大小的缓冲区）：生产者负责生成数据并将其放入固定大小的缓冲区中，而消费者则负责从缓冲区中取出数据。面临的挑战包括：当缓冲区已满时，生产者必须等待；当缓冲区为空时，消费者必须等待；同时，双方都必须避免破坏缓冲区的内容。

- 解决方案是使用两个信号量（一个用于统计空闲槽位，另一个用于统计已占用槽位），再加上一个用于管理缓冲区的互斥锁。这种机制也是大多数消息队列、日志系统以及数据管道所采用的基础。

- **读写冲突问题**：多个读取者可以同时进行读取操作，但写入者需要独占访问权。这里的挑战在于如何保证公平性——如果不断有读取者到来，写入者可能会永远无法获得访问权限。解决方法是优先处理读取者或写入者，或者让两者交替使用资源。

- **哲学家进餐问题**：五位哲学家围坐在一张桌子旁，每人面前有两把叉子。要进食的话，每个人需要两把叉子。如果五个人同时拿起自己的左叉子，那么就没人能拿到右叉子，最终所有人都会饿死（即出现死锁）。解决方法包括：一次性拿起两把叉子；引入不对称性（让某位哲学家先拿起右叉子）；或者设置“服务员”角色（通过信号量限制同时进餐的人数为4人）。

## 死锁

- 当一组线程各自都在等待另一线程所持有的资源时，就会发生死锁，从而形成依赖循环。此时，没有任何线程能够继续执行任务。

![死锁示意图：线程A持有锁1并希望获得锁2，而线程B持有锁2并希望获得锁1——形成循环等待](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/deadlock_cycle.svg)

- 死锁发生的四个**必要条件**（必须同时满足）：

1. **互斥性**：某个资源只能被一个线程持有。
2. **持有并等待**：一个线程在持有某个资源的同时，又在等待另一个资源。
3. **不可抢占性**：不能强制从某个线程手中夺走其所持有的资源。
4. **循环等待**：在等待关系图中存在循环。

- **死锁预防**的方法是打破上述四个条件中的某一个：
- 消除循环等待：为资源设定一个总顺序，所有线程都按照相同的顺序获取资源。如果每个线程都始终先获取锁A再获取锁B，那么就不可能出现循环等待。
- 消除“持有并等待”现象：要求线程一次性请求所有需要的资源（以原子方式）。

- **死锁避免**的方法则是动态判断是否批准某个资源请求，以避免死锁的发生。**银行家算法**会记录每个线程的最大需求量，只批准那些不会使系统陷入“安全状态”的请求（即一种所有线程最终都能完成任务的状态）。该算法处理每个请求的复杂度为$O(n^2 m)$（其中$n$为线程数量，$m$为资源类型数量），对于大多数实际系统来说效率过高。

- **死锁检测**的方法则是允许死锁发生，然后通过检测等待关系图中的循环来发现死锁，之后再采取恢复措施（如终止某个线程或回滚事务）。

- 在实际应用中，大多数系统对于常见情况采用死锁预防策略（如资源顺序控制），而对于罕见情况则采用死锁检测策略。数据库系统就是典型的例子：它们能够检测到事务之间的死锁，并中止其中一个事务以打破死锁循环。

## 无锁及无等待数据结构

- 锁会引发竞争、优先级反转以及死锁风险。**无锁**数据结构则完全避免了锁的使用，而是利用硬件提供的**原子操作**来实现功能。

- 最重要的原子操作是**比较并交换（CAS）**：它能够以原子方式检查某个内存位置的值是否与预期值相同，如果相同，则将其替换为新的值。用伪代码表示如下：

```text
CAS(address, expected, new_value):
    if *address == expected:
        *address = new_value
        return true
    else:
        return false
```

- CAS被实现为一种单一的硬件指令，因此即便没有锁的存在，它也具有原子性。无锁算法会在重试循环中使用CAS：先读取当前值，计算出新值，然后尝试执行CAS操作。如果在此期间有其他线程修改了该值，CAS操作就会失败，线程需要重新尝试。

- **无锁**：至少有一个线程能在有限的步骤内取得进展（不会发生死锁，但在竞争情况下，单个线程可能会无限重试）。

- **无等待**：每个线程都能在有限步数内取得进展（这是最强的保障，但实现起来最为困难）。

- 无锁栈、队列和哈希表被广泛用于高性能系统中。Java的`ConcurrentHashMap`以及Go语言中的原子操作都是基于CAS实现的。

## 并行编程模型

- **共享内存并行**：所有线程访问同一个内存空间。同步工作由程序员负责。**OpenMP**提供了用于实现循环并行的编译器指令：

```c
#pragma omp parallel for
for (int i = 0; i < n; i++) {
    result[i] = compute(data[i]);
}
```

- 编译器会将循环迭代任务分配到各个可用的核心上执行。OpenMP非常适合处理数据并行型任务（即对多个数据点执行相同的操作），因此在科学计算领域被广泛使用。

- **消息传递式并行性**：每个进程都有独立的内存空间，进程间的通信是通过发送和接收消息来实现的。**MPI**（消息传递接口）则是节点间进行分布式计算的标准化标准。

```c
MPI_Send(data, count, MPI_FLOAT, dest, tag, MPI_COMM_WORLD);
MPI_Recv(data, count, MPI_FLOAT, src, tag, MPI_COMM_WORLD, &status);
```

- MPI能够扩展到数千个节点，因为无需通过共享状态来实现同步。分布式深度学习（第6章）则利用`MPI_AllReduce`等集合操作来同步各GPU上的梯度值。

- **GPU并行性**遵循**SIMT**（单指令多线程）模型：数千个线程针对不同的数据执行相同的指令。这种架构非常适合矩阵运算（第2章），因为在矩阵运算中需要对每个元素执行相同的乘加操作。我们将在后面的章节中详细讲解GPU编程。

## 异步与事件驱动编程

- 并非所有的并发场景都需要线程。**异步**编程可以通过单个线程以及**事件循环**来处理大量I/O密集型任务。

- 事件循环会维护一个任务队列。当某个任务需要等待I/O操作完成（如网络响应、文件读取）时，它会注册一个回调函数，然后让出控制权。事件循环会接着处理下一个就绪的任务。一旦I/O操作完成，该回调函数就会被放入队列中，最终被执行。在等待过程中没有线程会被阻塞。

- **协程**是那些可以暂停和恢复执行的函数。Python、JavaScript和Rust中的`async/await`语法使得协程看起来就像普通的顺序代码一样：

```python
async def fetch_data(url):
    response = await http_get(url)  # suspends here, event loop runs other tasks
    return process(response)         # resumes when response arrives
```

- `await` 关键字会暂停协程，并将控制权交还给事件循环。当被等待的操作完成时，协程会从中断处继续执行。这是一种协作式多任务处理方式：协程是主动让出控制权的，而抢占式多任务处理则是由操作系统强制切换线程。

- 异步编程非常适合那些需要处理大量并发连接的**I/O密集型**任务（比如处理数千个客户端的Web服务器）。但它不适用于**CPU密集型**任务——单线程的事件循环无法利用多个核心。对于CPU密集型任务，应使用线程或进程。

- Python的**全局解释器锁（GIL）**阻碍了真正的多线程并行：同一时间只能有一个线程执行Python字节码。正因如此，Python在处理CPU密集型任务时采用多进程方式（每个进程都有独立的解释器），而在处理I/O密集型任务时则使用异步编程。从Python 3.13版本开始，GIL将被移除，从而实现真正的多线程并行。

## 扩展定律

- **阿姆达尔定律**描述了通过并行化程序所能获得的理论加速比。如果程序中有比例为$p$的部分可以并行处理，而剩余的$1 - p$部分则必须顺序处理：

$$\text{加速比}(n) = \frac{1}{(1-p) + \frac{p}{n}}$$

![阿姆达尔定律：顺序处理的部分限制了最大加速比——如果有10%的任务是顺序处理的，那么无论有多少核心，最大加速比也只有10倍](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/amdahl_serial_bottleneck.svg)

- 其中$n$表示处理器的数量。当$n \to \infty$时，最大加速比趋近于$\frac{1}{1-p}$。如果程序中有95%的部分可以并行处理，那么无论添加多少核心，最大加速比都是$\frac{1}{0.05} = 20\times$。顺序处理的部分就是性能瓶颈。

- 这一原理对机器学习领域有着重要影响：如果数据加载占训练时间的10%，且该过程是顺序处理的，那么增加GPU的数量最多也只能使训练速度提升10倍。这10%的顺序处理瓶颈限制了整体性能（这也是为什么高效的数据处理流程以及让计算与I/O操作同步进行如此重要的原因，详见第6章）。

- **古斯塔夫森定律**则提供了一种更为乐观的观点。它不是固定问题规模然后增加处理器，而是固定总时间，再看看还能完成多少工作。如果可并行处理的部分与问题规模成正比：

$$\text{加速比}(n) = 1 - p + p \cdot n$$

- 此时加速比与$n$呈线性关系。其逻辑是：有了更多处理器后，我们可以解决更大的问题，而不是更快地解决同一个问题。在机器学习中，这意味着可以通过增加GPU来提高批量处理的大小（弱扩展性），而非保持批量大小不变（强扩展性）。

1. 演示竞态条件现象。让两个线程在没有同步机制的情况下同时递增一个共享计数器，观察由此产生的数据丢失现象。

```python
import threading

counter = 0

def increment(n):
    global counter
    for _ in range(n):
        counter += 1  # NOT atomic: read, add, write

threads = [threading.Thread(target=increment, args=(100000,)) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()

print(f"Expected: {4 * 100000}")
print(f"Actual:   {counter}")
print(f"Lost updates: {4 * 100000 - counter}")
```

1. 使用锁来解决竞态条件问题，并测量由此产生的开销。

```python
import threading
import time

lock = threading.Lock()
counter = 0

def increment_locked(n):
    global counter
    for _ in range(n):
        with lock:
            counter += 1

start = time.time()
threads = [threading.Thread(target=increment_locked, args=(100000,)) for _ in range(4)]
for t in threads: t.start()
for t in threads: t.join()
elapsed = time.time() - start

print(f"Counter: {counter} (correct: {4 * 100000})")
print(f"Time with lock: {elapsed:.3f}s")
```

1. 可视化阿姆达尔定律。绘制不同并行度下处理速度与处理器数量之间的关系曲线。

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

n_procs = jnp.arange(1, 65)

for p, color in [(0.5, "#e74c3c"), (0.9, "#f39c12"), (0.95, "#27ae60"), (0.99, "#3498db")]:
    speedup = 1 / ((1 - p) + p / n_procs)
    plt.plot(n_procs, speedup, color=color, linewidth=2, label=f"p={p}")
    # Max speedup line
    plt.axhline(1 / (1 - p), color=color, linestyle="--", alpha=0.3)

plt.xlabel("Number of processors")
plt.ylabel("Speedup")
plt.title("Amdahl's Law: Serial Fraction Limits Speedup")
plt.legend()
plt.grid(True)
plt.show()
```

## 编程语言

_编程语言是人类意图与机器执行之间的桥梁。本文件涵盖了编程范式、类型系统、内存管理策略、编译流程、解释执行与即时编译机制、各种语言的关键特性、领域专用语言以及设计上的权衡因素。_

- 所有的软件、机器学习模型以及操作系统都是用某种编程语言编写的。不过，现有的编程语言有数百种，每种都有其独特的优势。为什么会这样呢？因为语言的设计涉及到一系列根本性的权衡：性能与安全性、表达能力与简洁性、控制力与抽象程度。了解这些权衡有助于我们选择最适合当前任务的工具，同时也能明白自己所面临的限制。

## 编程范式

- **编程范式**是一种编程风格，即一套指导我们如何组织代码以及如何思考问题的原则。

- **命令式编程**将计算过程视为一系列用于改变程序状态的指令。“将x的值设为5。再给x加上3。如果x大于7，则输出它的值。”C语言、Python和Java都属于命令式编程语言。其思维模型就是一台可以逐步被修改的带内存的机器。

- **面向对象编程**则是以**对象**作为代码的组织单元：对象由数据（属性）和行为（方法）组成。对象之间通过互相发送消息来交互。其核心理念包括**封装**（将内部状态隐藏在公共接口之后）、**继承**（通过扩展现有类来创建新类）以及**多态**（通过共享接口来统一处理不同类型的数据）。Java、C++和Python都支持面向对象编程。

- **函数式编程**则将计算视为数学函数的求值过程。其核心原则包括：**不可变性**（数据一旦创建就不会再发生变化）、**纯函数**（函数的输出仅取决于输入，没有副作用），以及**一等函数**（函数可以被当作参数传递、从其他函数中返回，还可以存储在变量中）。Haskell就是纯粹的函数式编程语言。Python、JavaScript和Scala也支持函数式编程风格。

- 纯函数便于理解、测试以及并行处理（由于不存在共享的可变状态，因此也就不会出现竞态条件）。正因如此，函数式编程理念越来越多地被应用于分布式系统和数据处理流程中。本书中使用的JAX也是一种函数式语言：`jax.grad`能够正常工作，正是因为JAX中的函数都是纯函数。

- **逻辑编程**则侧重于描述“什么”是真实的，而非“如何”去计算它。用户只需陈述事实与规则，运行时系统会自动找出解决方案。Prolog就是典型的逻辑编程语言示例：给定“苏格拉底是人”以及“所有人都会死亡”这两个事实，该语言就能推导出“苏格拉底也会死亡”。逻辑编程被广泛应用于人工智能知识库和类型检查中。

- 大多数现代编程语言都是**多范式**的：Python支持命令式、面向对象和函数式编程风格；Rust则支持命令式和函数式编程。编程范式只是一种工具，而非必须遵循的规则。

## 类型系统

- **类型**用于对数值进行分类，并决定哪些操作是允许的。整数3和字符串“3”属于不同的类型：整数可以相加，但字符串则不能（当然，字符串可以拼接，但这属于另一种操作）。

- **静态类型**是指在程序运行之前，即在**编译阶段**就对类型进行检查。这样一来，类型错误就能在早期被发现。C语言、Java、Rust和Go都属于静态类型语言。开发者必须明确声明类型，或者让编译器自行推断类型。

```rust
let x: i32 = 5;     // Rust: x is a 32-bit integer
let y: f64 = 3.14;  // y is a 64-bit float
// let z = x + y;    // compile error: cannot add i32 and f64
```

- **动态类型**：类型检查在**运行时**进行，也就是在代码实际执行时才会进行。这种方式更加灵活，但类型错误只有在代码运行时才会被发现。Python、JavaScript和Ruby都属于动态类型语言：

```python
x = 5       # x is an int (for now)
x = "hello" # now x is a string -- no error
```

- **强类型**：这种语言会防止隐式的类型转换。Python属于强类型语言，执行“3”+5”时会引发TypeError错误。**弱类型**：这种语言会自动进行类型转换。JavaScript就是弱类型语言，执行“3”+5”后会得到“35”，因为数字被自动转换为字符串。C语言也是弱类型语言，可以将指针转换为整数。

- **类型推断**功能允许编译器在无需显式标注的情况下推断出类型：

```rust
let x = 5;        // compiler infers: i32
let y = x + 3.0;  // compile error: mixed types, even with inference
```

- **泛型**（参数化多态性）使得你可以编写能够处理任意类型的代码：

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in &list[1..] {
        if item > max { max = item; }
    }
    max
}
// Works for integers, floats, strings -- any type that supports comparison
```

- 对于机器学习而言：Python的动态类型特性使得实验效率很高，但也会隐藏错误。在实际的机器学习系统中，人们越来越多地使用类型提示（如`def train(model: nn.Module, lr: float) -> float`）以及静态分析工具（如mypy），以便在程序部署之前发现错误。PyTorch和JAX采用Python语言以获得灵活性；而TensorRT和ONNX Runtime则使用C++语言来提升性能。

## 内存管理（续1）

- 每个程序都会进行内存的分配与释放。如何管理内存是编程语言设计中极为重要的决策之一。

![内存结构：栈从高地址向低地址扩展，堆则从低地址向高地址扩展，代码和数据位于最底部](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/stack_vs_heap.svg)

- **栈**用于存储局部变量和函数调用帧。内存的分配非常简单（只需移动栈指针），而释放则是在函数返回时自动完成的。由于栈始终处于缓存中，因此访问速度很快。不过栈的大小是固定的（通常为1-8 MB），且只支持后进先出式的内存分配方式。

- **堆**用于存储那些在编译时大小尚不确定的动态分配数据（如对象、数组、字符串等）。在堆上分配内存的速度较慢（需要找到空闲的内存块），并且必须手动或自动地进行内存释放。堆的大小可以随着可用内存的增加而扩大。

- **手动内存管理**（C、C++）：程序员需要手动为堆内存分配空间（使用`malloc`函数）并释放空间（使用`free`函数）。这种方式能够实现最大的控制权与最佳性能，但也极易出现错误：
- **越界访问已释放的内存**：试图访问已经被释放的内存，会导致程序崩溃或出现安全漏洞。
- **重复释放内存**：对同一块内存进行两次释放，会破坏内存管理器的内部数据结构。
- **内存泄漏**：分配了内存却从未释放它，这样程序会逐渐耗尽所有可用内存。

- **垃圾回收**：运行时系统会自动检测并释放那些不再被使用的记忆。程序员无需手动调用`free`函数。

- **追踪式垃圾回收**（Java、Go、Python的循环收集器）：定期从“根节点”（如栈变量、全局变量）开始遍历所有可访问的对象，然后释放那些不可访问的对象。这种方式的实现较为简单，但会导致**垃圾回收暂停**——即程序会在垃圾回收过程中暂停执行。现代的垃圾回收器（如Go的并发垃圾回收器、Java的ZGC）已将暂停时间缩短到毫秒级以内。

- **引用计数**（Python的主要机制，Swift、Objective-C也采用此方式）：每个对象都会记录有多少个引用指向它。当引用计数降为0时，该对象就会被立即释放。这种方式不会导致暂停，但无法处理**循环引用**的情况（例如A引用B，B又引用A，此时两者的引用计数都大于0，但却都无法被访问）。Python则通过专门的循环检测机制来解决这个问题。

- **所有权机制**（Rust）：编译器会在编译阶段就强制实施内存安全规则，从而无需任何运行时开销。

- 每个值都有且仅有一个**所有者**。当所有者离开作用域时，该值就会被释放。
- 值可以被**借用**，但编译器规定：要么只有一个可修改的引用，要么有任意多个不可修改的引用，绝不能同时存在两种引用。
- 这种机制能够在编译阶段就避免越界访问、重复释放、数据竞争以及悬空指针等问题。Rust无需垃圾回收，也没有运行时开销。

- **借用检查器**是Rust的强大特性，也是其学习曲线最陡的部分。它能够在不依赖垃圾回收的情况下确保内存安全和线程安全，正因如此，Rust越来越被用于那些对性能要求极高的系统中，比如操作系统内核、游戏引擎，以及Candle和Burn之类的机器学习推理引擎。

## 编译流程

- **编译器**的作用是在程序运行之前，将源代码转换为机器码（或其他目标语言的代码）。整个编译过程包含多个阶段：

![编译流程：源代码 → 词法分析器 → 语法分析器 → 语义分析 → 优化器 → 代码生成 → 机器码](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/compilation_pipeline.svg)

1. **词法分析**：将源代码转换为一连串的令牌。例如，`x = 3 + y`会被转换为`[IDENT("x"), EQUALS, INT(3), PLUS, IDENT("y")]`。词法分析器还会去除其中的空白字符和注释。

1. **语法分析**：根据这些令牌构建一个**抽象语法树**。抽象语法树反映了程序的层次结构。例如，`3 + y * 2`会被解析为`Add(3, Mul(y, 2))`，因为乘法的优先级高于加法。语法分析器还会检查代码的语法结构，及时发现括号不匹配或缺少分号等问题。

1. **语义分析**：检查数据的类型，确定变量名称的正确性，确保函数被正确地调用。这一阶段会进行静态类型检查，最终得到一个带有类型标注的抽象语法树。

1. **优化**：对程序进行优化，使其在保持原有功能的前提下运行得更快。常见的优化手段包括：

- **常量折叠**：在编译时就计算出`3 + 5`的结果，将其替换为`8`。
- **删除无用代码**：移除那些永远不会被执行的代码。
- **循环展开**：将循环替换为多行连续的代码，从而减少分支判断的开销。
- **内联处理**：将函数调用直接替换为函数体，从而消除调用带来的开销。

1. **代码生成**：将经过优化的代码转换为目标机器码（如x86、ARM格式），或者转换为中间表示形式。

- **LLVM**是目前最主流的编译器框架。它提供了一种通用的中间表示形式——LLVM IR，许多编程语言都可以将其代码转换为这种形式。LLVM的优化器可以在这种中间表示上工作，而它的后端则负责为不同的目标平台生成机器码。Clang（用于C/C++）、Rust、Swift、Julia以及许多其他编程语言都采用了LLVM。这意味着，一旦LLVM的优化器得到改进，所有使用这些语言的程序都能受益。

## 解释执行与即时编译

- **解释器**会逐行（或逐条语句）执行程序，而不生成机器码。这种方式使得程序启动速度快，开发过程也更加便捷，但程序的执行速度较慢——因为每行代码在每次执行时都需要重新分析。

- 实际上，大多数解释型语言都会先将代码编译为**字节码**：这是一种比源代码更简单，但又不是特定于某种机器的中间表示形式。字节码会在**虚拟机**上运行。
- **CPython**（标准的Python实现）会将Python源代码编译为字节码（`.pyc`文件），这些字节码由CPython虚拟机来执行。该虚拟机会逐条解释字节码。正因如此，对于那些需要大量计算的程序来说，Python的运行速度比C语言慢约100倍。

- **JVM**（Java虚拟机）：Java代码会被编译为JVM字节码（`.class`文件）。JVM首先会解释这些字节码，然后对那些被频繁调用的代码路径（“热点代码”）进行JIT编译，将其转换为机器码。这就是为什么Java的启动速度比C语言慢（因为有解释开销），但对于那些需要长时间运行的程序来说，其速度却可以接近C语言的速度（因为有了JIT优化）。

- **JIT（即时编译）**是一种在运行时将代码编译为机器码的技术，它利用的是仅在程序执行过程中才能获取的信息。JIT可以根据实际的运行数据来进行优化：如果某个函数总是接受整数作为参数，那么JIT就会生成专门的、仅处理整数的机器码，从而省去类型检查的步骤。

- **PyPy**是另一种带有JIT编译器的Python实现。通过将那些被频繁调用的代码块编译为机器码，PyPy的运行速度比CPython快5到10倍。不过，它与C语言编写的扩展模块（如NumPy、PyTorch）的兼容性较差，这限制了它在机器学习领域的应用。

- 从解释型到编译型的过渡并非非黑即白的：
- 纯解释型：Bash Shell脚本。
- 字节码解释型：CPython。
- 字节码+JIT型：JVM、.NET CLR、LuaJIT、PyPy。
- 提前编译型：C、C++、Rust、Go。
- 提前编译+运行时代码生成型：JAX的`jax.jit`功能会在首次调用时将Python函数编译为优化的XLA代码，之后则缓存该编译后的版本。

## 主要语言特性

- **闭包**：一种能够捕获其所在作用域中变量的函数。这样的函数会“绑定”在其被定义时的环境之中。

```python
def make_adder(n):
    def add(x):
        return x + n  # n is captured from the enclosing scope
    return add

add5 = make_adder(5)
print(add5(3))  # 8
```

- 闭包是回调函数、装饰器以及部分应用功能背后的实现机制。它们是函数式编程中的核心概念。

- **模式匹配**：这是一种强大的控制流机制，能够根据数据的结构来对其进行分析，并据此选择不同的执行路径。

```rust
match value {
    Some(x) if x > 0 => println!("Positive: {}", x),
    Some(0)           => println!("Zero"),
    Some(x)           => println!("Negative: {}", x),
    None              => println!("Nothing"),
}
```

- 模式匹配比if-else链更具表达力：它能够检查数据的结构（是Some还是None？是否包含符合某种条件的值？），而不仅仅是判断相等性。Python在3.10版本中加入了结构化模式匹配功能（`match`/`case`）。

- **代数数据类型（ADTs）**：这类类型可以有多种形态，每种形态对应不同的数据。`Result`类型要么是`Ok(value)`，要么是`Err(error)`；`Tree`类型要么是`Leaf(value)`，要么是`Node(left, right)`。将代数数据类型与模式匹配结合使用，就可以全面处理所有可能的情况，从而避免各类错误（如空指针异常、未处理的错误代码等）。

- **特性与接口**：用于规定某个类型必须实现的一组方法，但不指定具体的实现方式。这便实现了多态性：一个接受“任何实现了Display特性的对象”的函数，可以用于处理整数、字符串以及自定义类型。Rust使用特性，Java使用接口，Go使用隐式接口，而Python则采用“鸭子型”原则（“只要行为像鸭子，那就是鸭子”）。

## 领域特定语言

- **领域特定语言（DSL）**是为解决特定问题而设计的，它牺牲了通用性，以换取在该领域的强大表达能力。

- **SQL**：关系数据库所使用的语言。`SELECT name FROM users WHERE age > 30`这样的查询语句，比相应的循环结构更易理解，也更容易被优化。数据库引擎会自动优化查询执行计划，选择合适的连接策略和索引使用方式。

- **正则表达式**：一种用于文本模式匹配的微型语言。`\d{3}-\d{4}``可以匹配像“555-1234”这样的电话号码。正则表达式引擎会将这些模式编译为有限自动机，从而实现高效的匹配操作。

- **着色器语言**（GLSL、HLSL、Metal Shading Language）：这类程序在GPU核心上运行，用于计算像素颜色、顶点位置或执行各种计算操作。着色器具有高度并行性：每次调用都会独立处理一个像素或一个元素。这与CUDA在机器学习计算中所采用的执行模型相同。

- 在机器学习领域，PyTorch和JAX这类框架本质上就是用于张量计算的领域特定语言，它们嵌入在Python环境中。这些框架提供了针对特定领域的抽象概念（如张量、自动微分、设备分配等功能），同时还能充分利用Python的生态系统。

## 语言设计中的权衡

- 没有一种语言能在所有方面都表现最佳。语言设计的关键在于决定要做出哪些权衡：

- **性能与安全性**：C语言具有极高的运行速度和硬件控制能力，但同时也允许用户破坏内存结构。Rust则能在保持相近性能的同时确保内存安全。Java通过垃圾回收机制来保证内存安全，但会带来一定的性能开销。Python则能在确保最高安全性和强大表达力的同时，以慢100倍的执行速度作为代价。

- **表达力与简洁性**：Haskell的类型系统能够实现非常精确的约束条件，但学习曲线较为陡峭。Go为了简化设计，刻意省略了泛型、继承和异常机制（直到最近才加入这些功能）。Python遵循“应该有一种最直观的实现方式”的理念，因此这种语言相对容易学习。

- **控制性与抽象性**：C/C++允许开发者控制内存布局、缓存行为以及与硬件的交互方式。而Python则隐藏了所有这些细节。在需要大量使用GPU进行计算的机器学习任务中，Python的性能开销可以忽略不计。但在对时间要求极为严格的机器学习推理任务中，可能需要使用C++或Rust。

- **编译速度与运行速度**：Go的编译速度很快，只需几秒钟（因为其类型系统简单，优化程度较低）。而Rust的编译则需要几分钟时间（因为其类型系统较为复杂，且优化程度很高）。这种权衡实际上是在开发者的迭代速度与最终程序的性能之间做出的选择。

- 机器学习领域也体现了这些权衡：Python适合用于实验和训练阶段，因为其强大的表达力更具优势；C++/CUDA则更适合用于编写内核代码和进行推理计算，因为其性能更优；而Rust则适用于构建基础设施以及那些对安全性要求极高的系统。

1. 探索闭包和高阶函数。实现一个简单的函数工厂，并验证闭包确实能够捕获其所在的环境信息。

```python
def make_multiplier(factor):
    """Returns a function that multiplies by factor."""
    def multiply(x):
        return x * factor
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(f"double(5) = {double(5)}")  # 10
print(f"triple(5) = {triple(5)}")  # 15

# Closures capture by reference, not by value
def make_counter():
    count = [0]  # mutable container to allow modification
    def increment():
        count[0] += 1
        return count[0]
    return increment

counter = make_counter()
print(f"counter() = {counter()}")  # 1
print(f"counter() = {counter()}")  # 2
print(f"counter() = {counter()}")  # 3
```

1. 比较动态类型与静态类型的特性。说明Python的动态类型机制如何带来灵活性，但同时也可能掩盖错误。

```python
def add(a, b):
    return a + b

# Works with different types -- flexible!
print(add(3, 5))           # 8 (int + int)
print(add("hello ", "world"))  # "hello world" (str + str)
print(add([1, 2], [3, 4]))    # [1, 2, 3, 4] (list + list)

# But type errors only surface at runtime:
try:
    print(add("hello", 5))  # TypeError! str + int
except TypeError as e:
    print(f"Runtime error: {e}")
    print("A static type checker would catch this before running")
```

1. 测量在计算密集型任务中，解释型Python与编译型/JIT版本在性能上的差异。

```python
import time
import jax
import jax.numpy as jnp

n = 1_000_000

# Pure Python loop (interpreted)
start = time.time()
total = 0.0
for i in range(n):
    total += i * i
python_time = time.time() - start

# JAX (compiled via XLA)
@jax.jit
def sum_squares_jax(n):
    return jnp.sum(jnp.arange(n, dtype=jnp.float32) ** 2)

_ = sum_squares_jax(10)  # warm up JIT
start = time.time()
result = sum_squares_jax(n)
jax_time = time.time() - start

print(f"Python loop: {python_time:.4f}s")
print(f"JAX (JIT):   {jax_time:.6f}s")
print(f"Speedup:     {python_time / jax_time:.0f}x")
```
