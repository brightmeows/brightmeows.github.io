## 感知

_感知是指自主系统如何感知并解读物理世界。本文件涵盖了传感器类型、传感器校准、传感器融合、3D物体检测、深度估计、占用网格、车道检测以及语义映射等内容——这些都是所有机器人、无人机和自动驾驶汽车所依赖的感知基础。_

- 对于人类来说，感知世界是毫不费力的：看到有汽车靠近，听到引擎声，感受到脚下的地面，就能立刻在脑海中形成对周围环境的认知。自主系统也需要做到同样的事情，只不过它使用的是电子传感器和算法，而非眼睛和耳朵。

- 最根本的挑战在于：传感器只能提供原始数据（如像素强度、点云、信号反射值），系统必须将这些数据转化为结构化的信息，例如“12米前方有一名行人，正以1.5米/秒的速度向左移动”。这就是感知问题所在。

- 所有的后续处理（预测、规划、控制）都依赖于感知能力。即便一辆汽车的规划功能再完美，但如果其感知能力较差，仍然会导致事故。因此，感知能力是整个系统的瓶颈。

## 传感器类型

- 自主系统会使用多种类型的传感器，每种传感器都有各自的优点和缺陷。没有任何一种传感器能够单独满足所有需求。

![传感器对比：从分辨率、深度感知能力、抗恶劣天气性能、速度测量精度以及成本等方面对相机、激光雷达、雷达和惯性测量单元进行比较](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/sensor_comparison.svg)

- **相机**能够以高分辨率捕捉丰富的颜色信息。一张图像包含数百万个像素，每个像素都记录着RGB数值（如第8章所述）。相机价格低廉、重量轻，还能提供丰富的纹理和颜色信息，这些信息对于识别标志、检测交通信号灯以及辨认物体非常重要。

- 相机的类型包括**单目相机**（只有一个镜头，无法直接获取深度信息）、**双目相机**（两个镜头之间有一定距离，通过视差来计算深度，详见第8章）以及**鱼眼相机**（具有超宽的视野范围，可达180°以上，但存在严重的径向畸变，常用于全景停车系统）。

- 相机的主要缺点在于，在将3D场景投影到2D图像平面时，会丢失深度信息。根据针孔相机模型，3D场景会被映射到2D图像上（可回想一下第8章中的内参矩阵$K$）：

$$\begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \frac{1}{Z} K \begin{bmatrix} X \\ Y \\ Z \end{bmatrix}$$

- 分母中的$Z$会导致绝对深度信息的丢失。两个大小不同、距离也不同的物体，其投影结果可能完全相同。因此，仅凭一张图像很难恢复出物体的深度，这就需要使用双目相机或经过训练的单目深度检测模型。

- 在恶劣环境下，相机的性能也会下降：强光会导致反光，黑暗环境则会使信号强度降低，而雨雪则会使光线散射。

- **激光雷达**通过发射激光脉冲，并测量每个脉冲反射回来所需的时间来工作。由于光速是已知的（$c \approx 3 \times 10^8$ 米/秒），因此可以计算出到各个反射点的距离：

$$d = \frac{c \cdot \Delta t}{2}$$

![激光雷达的飞行时间原理：激光脉冲照射到物体上后反射回来，根据往返时间即可计算出距离](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/lidar_time_of_flight.svg)

- 乘以2是因为光需要往返一次。通过让激光在场景中扫过，激光雷达可以生成**点云**——即一组3D坐标$(x, y, z)$，这些坐标通常还包含反射强度信息。

- **旋转式激光雷达**（如Velodyne系列）可以通过360°旋转激光阵列来获得全方位的视野。这类设备每秒可以生成30万多个点，覆盖64–128个垂直通道。最终得到的结果是场景的稀疏但几何精度很高的3D表示。

- **固态激光雷达**没有活动部件，而是采用光学相控阵或MEMS镜片来替代传统组件。这使得它们更便宜、更紧凑、更可靠，但视野范围通常较窄（120°而非360°）。

- 激光雷达能够提供精确的深度信息，但生成的点数较少（远少于相机），且没有颜色信息，同时价格也较高。在暴雨、大雪或灰尘环境中，激光脉冲会被颗粒物散射，从而导致性能下降。

- **雷达**与激光雷达一样基于飞行时间原理工作，但它使用的是无线电波（通常是77 GHz的毫米波）。无线电波比光更能穿透雨、雾、灰尘和雪，因此雷达是抗恶劣天气能力最强的传感器。

- 雷达还可以通过多普勒效应直接测量物体的**速度**。当物体朝传感器移动时，反射波的频率会升高；而当物体远离传感器时，反射波的频率则会降低。速度的计算公式为：

$$v = \frac{\Delta f \cdot c}{2 f_0}$$

其中$\Delta f$是频率变化量，$f_0$是发射频率。这样就可以无需任何跟踪或帧间计算就能得到物体的瞬时径向速度。

- 雷达的缺点是角度分辨率较低，因此难以区分附近的物体或检测细微细节。不过，它在任何天气条件下都能在200米以上的距离准确检测到车辆。

- **超声波传感器**会发射高频声波脉冲（40–70 kHz），并测量回波的返回时间。它们的作用范围非常有限，仅为0.2–5米，主要用于辅助停车。其工作原理与激光雷达类似，只是用声波代替光波，因此距离计算公式为$d = \frac{v_{\text{声音}} \cdot \Delta t}{2}$，其中$v_{\text{声音}} \approx 343$ 米/秒。

- **惯性测量单元**包含加速度计和陀螺仪，分别用于测量线性加速度和角速度。惯性测量单元能够提供高频的运动数据（通常为200–1000赫兹），从而填补其他传感器更新之间的空白。它们并不直接感知环境，而是记录机器人的自身运动情况，因此对于定位和状态估计来说至关重要。
- IMU存在**漂移问题**：微小的测量误差会随着时间不断累积，导致估算出的位置与实际位置出现偏差。正因如此，IMU几乎总是与其他传感器（如摄像头、GPS、LiDAR）结合使用，而非单独使用。

- **GNSS**（全球导航卫星系统，包括GPS）通过多颗卫星发出的信号进行三角定位，从而确定地球表面的绝对位置。标准GPS的精度为2–5米，这一精度不足以满足车道级驾驶的需求。**RTK-GPS**（实时动态差分GPS）则利用固定基站来修正误差，可实现厘米级精度，但需要良好的天空视野以及相应的基站基础设施。

## 传感器标定

- 在多个传感器能够协同工作之前，必须先对它们进行**标定**：每个传感器的测量结果都需要与统一的坐标系相对应。

- **内在标定**用于确定传感器的内部参数。对于摄像头而言，这些参数包括焦距、主点以及畸变系数（详见第8章）。对于LiDAR来说，则是指激光束之间的精确角度差异。一种常用的标定方法是张氏棋盘格标定法，即从多个角度观察已知的平面图案，以此求解内在矩阵。

- **外在标定**则是用来确定两个传感器之间的刚性变换关系（旋转矩阵$R$和平移向量$\mathbf{t}$）。如果摄像头和LiDAR安装在同一辆车上，外在标定就能得到一个$4 \times 4$的变换矩阵，该矩阵可将LiDAR坐标系的点转换为摄像头坐标系的点：

$$\mathbf{p}_{\text{cam}} = \begin{bmatrix} R & \mathbf{t} \\ \mathbf{0}^T & 1 \end{bmatrix} \mathbf{p}_{\text{lidar}}$$

- 这是一种齐次坐标系下的仿射变换，与我们第2章中所学的线性变换属于同一类型。如果这个矩阵计算有误，那么LiDAR检测到的点就会映射到错误的像素位置，进而导致整个融合流程失效。

- **时间标定**则用于同步各传感器的时钟。如果摄像头的采样率为30赫兹，而LiDAR的采样率为10赫兹，那么它们产生的数据就会具有不同的时间戳。当汽车以30米/秒的速度行驶时，10毫秒的时间误差就相当于30厘米的空间误差。因此，要么使用硬件触发方式（共享时钟脉冲），要么通过软件手段实现时间同步（在时间戳之间进行插值）。

## 传感器融合

- 没有任何一种传感器能够覆盖所有场景条件。摄像头可以识别颜色和纹理，但却无法获取深度信息；LiDAR虽然能精确测量深度，但其数据密度较低且无法识别颜色；雷达则可在任何天气条件下工作，但分辨率较差。**传感器融合**就是利用各种传感器的优势，同时弥补各自的缺陷。

- **早期融合**（或数据级融合）是在对数据进行处理之前，直接将各个传感器的原始数据结合起来。例如，将LiDAR检测到的点投影到摄像头图像上，从而生成包含颜色和深度信息的RGBD数据；或者用对应摄像头像素的颜色来标记每个LiDAR点。这种方法能够保留最多的信息，但要求精确的标定，而且对传感器之间的对准精度要求很高。

- **晚期融合**（或决策级融合）则是让每个传感器独立地经过自身的检测流程，之后再合并最终的输出结果（如边界框、类别标签、置信度得分）。每种传感器都会给出自己的判断，然后由融合模块来协调这些不同的判断结果。这种方法的实现较为简单，也更具模块化特性，但各个传感器无法利用其他传感器的原始数据。

- **中间级融合**则是在中间特征层面进行整合。首先将每个传感器的原始数据转换为学习得到的特征向量（可使用CNN或Transformer来实现），然后再将这些特征组合起来。这是现代系统中最常用的方法，因为它能让网络自行决定从每种传感器的数据中提取哪些有用信息。

![BEV融合流程：摄像头和LiDAR的原始数据会被分别编码，然后再投影到同一个鸟瞰式网格中](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/bev_fusion_pipeline.svg)

- **BEVFusion**是一种典型的中间级融合架构。它将摄像头的特征和LiDAR的特征都投影到同一个**鸟瞰式（BEV）表示**中，也就是场景的俯视网格结构。摄像头的特征会通过预测的深度分布被“提升”到3D空间，然后再映射到该网格上；而LiDAR的特征本身就是3D格式的，可以直接被映射到同一个网格上。最终，这些融合后的BEV特征会被送入检测模块进行处理。

- BEV表示方式的优势在于它提供了一个统一的、基于度量单位的坐标系，在这个坐标系下进行空间推理（如计算距离、大小、重叠程度）会非常方便。在摄像头图像中，附近的自行车和远处的卡车可能会占据相同的像素数量，但在BEV表示中，它们的真实大小和位置则一目了然。

## 3D物体检测

- 感知系统的核心任务就是检测3D空间中的物体：它们位于何处、大小如何、属于何种类型，以及它们的朝向是怎样的？每次检测的结果都会以一个**3D边界框**的形式呈现，其中包含位置信息$(x, y, z)$、尺寸信息$(l, w, h)$、朝向角度$\theta$、类别标签以及置信度得分。

- **基于LiDAR的检测方法**是直接对点云数据进行处理的。不过，点云数据是无序的、形状不规则的，而且其密度也各不相同——靠近的物体会有数千个点，而远处的物体则只有少数几个点。正如第8章所提到的，PointNet通过共享的多层感知器以及具有排列不变性的聚合方式（如最大池化操作）来解决这个问题。

- **PointPillars**方法则是通过将地面平面划分为一系列垂直的柱状结构，从而将点云转换为结构化的表示形式。每个柱状结构内的所有点都会通过一个小型PointNet模型被转换为一个固定大小的特征向量。这样处理后得到的就是一张2D伪图像，它可以被标准的2D CNN结构处理，之后再通过检测模块进行进一步分析（类似于第8章中介绍的SSD架构）。这种方法既快速又高效。
- **CenterPoint**将物体识别为点而非矩形框。它首先预测出物体中心在BEV坐标系中的热力图，然后在每个峰值处反推出矩形的各项属性（尺寸、高度、朝向、速度）。这实际上是CenterNet（第8章）的3D版本：无需锚点，在训练过程中也不需要NMS机制，而且通过跨帧关联各中心点，可自然实现物体跟踪功能。

- **仅依赖摄像头的3D检测**必须从2D图像中推断深度，这一任务本身就更为困难。像**BEVDet**和**BEVFormer**这样的现代方法则利用变换器架构将2D图像特征“提升”到3D空间。BEVFormer采用空间交叉注意力机制：BEV查询会关注投影到每个摄像头图像上的特定3D参考点，从而从相应位置获取特征。

- 随着深度估计技术的改进、模型规模的扩大以及时间融合技术的发展（通过多帧图像来积累深度信息，其原理类似于立体匹配，但是在时间维度上实现），基于激光雷达的3D检测与基于摄像头的3D检测之间的精度差距正在迅速缩小。

## 深度估计

- 深度估计是指为每个像素或点分配一个距离值的过程。

- **立体匹配**利用两个相距已知距离$b$的摄像头。同一个3D点在两个图像中的水平位置会有细微差异，这种差异被称为**视差**$d$。深度可通过以下公式计算（源自第8章）：

$$Z = \frac{f \cdot b}{d}$$

其中$f$为焦距。该方法的难点在于找到两个图像之间正确的对应关系，尤其是在缺乏纹理的区域、存在遮挡物或图案重复的情况下。现代立体匹配算法（如RAFT-Stereo）则通过相关体积进行迭代优化。

- **单目深度估计**则是仅通过单张图像来预测深度。由于这个问题存在不确定性（无数个3D场景都可能生成相同的图像），因此网络必须学习一些统计规律：“地面是平的”、“物体随距离增加而变小”、“纹理梯度可以反映表面的远近”。

- **Depth Anything**（详见第8章）通过在大规模无标签数据集上进行自监督训练，再在带标签的数据上进行微调，从而实现了强大的单目深度估计能力。其核心思路在于利用尺度不变损失来处理固有的不确定性：模型预测的是相对深度顺序，而非绝对数值。

- **激光雷达与摄像头的深度融合**则是将稀疏的激光雷达深度数据映射到摄像头图像上作为监督信号。网络由此学会填补这些稀疏点之间的空白，从而生成密集的深度图，结合了激光雷达的高精度与摄像头的高分辨率优势。

## 占用网格

- 传统的感知系统会为每个检测到的物体输出一个边界框。但实际上，现实世界中有很多物体无法被完美地纳入矩形框中：形状奇特的碎片、建筑围挡、伸出的树枝、部分倒塌的墙壁等等。

![边界框无法准确描述不规则形状；占用网格则能反映实际几何结构](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/occupancy_vs_bbox.svg)

- **占用网格**则将场景表示为密集的3D体素网格。每个体素（即一个小立方体，例如0.2米×0.2米×0.2米）会被标记为“空闲”、“被占用”或“未知”，必要时还会赋予其语义标签（如道路、人行道、车辆、植被等）。

- 这种方法代表了从以物体为中心的感知方式（“检测汽车”）向以场景为中心的感知方式（“3D空间的哪些区域被占用？”）的转变。其优势在于具有更强的通用性：系统无需预先定义物体类别列表，就能避免与各种随机障碍物发生碰撞。

- 在架构上，占用网格系统会接收来自摄像头、激光雷达或两者的传感器数据，将其编码为3D特征体，然后预测每个体素的类型。这个3D特征体通常是通过将2D特征提升到3D空间来构建的（类似BEV的构建方式，但是在垂直方向上扩展），之后再通过3D卷积或稀疏卷积进行处理。

- **TPVFormer**（三视角视图）通过将3D空间分解为三个正交平面（俯视、正面、侧面），避免了全3D注意力机制所带来的计算开销。每个平面都使用2D注意力机制，各平面的特征会在每个体素处进行整合。这一思路类似于SVD将矩阵分解为更简单的因子（见第2章）：将复杂的3D问题拆解为多个易于处理的2D问题。

- 最终得到的体素网格可以直接告诉规划器哪些空间区域是安全的，哪些不是，因此它成为了感知模块与规划模块之间的理想接口。

## 车道检测与道路拓扑结构

- 对于行驶在有明确道路结构的道路上的车辆而言，了解**车道几何形状**至关重要。系统需要知道车道的 위치、弯曲情况、交汇与分离点，以及车辆当前处于哪条车道上。

- 传统方法会将参数曲线拟合到检测到的车道标线上。常用的模型是三次多项式：

$$x(y) = a_0 + a_1 y + a_2 y^2 + a_3 y^3$$

其中$y$表示前方的纵向距离，$x$则表示横向偏移量。这是一种多项式近似方法（可回顾第3章中的泰勒级数），之所以选择这种方式，是因为道路通常是平滑的曲线，低阶多项式就能很好地描述它们。这些系数则是通过对检测到的车道点进行最小二乘回归来估算的。

- 现代方法则直接利用神经网络来检测车道。**LaneNet**将每条车道视为一个独立实体，先通过嵌入层将属于同一车道的像素归类在一起，然后再进行曲线拟合。**GANet**则采用基于图的方法，将车道拓扑结构表示为有向图，其中节点代表车道点，边则表示车道之间的连接关系（如哪些车道在交叉口交汇、分离或相连）。

- **道路拓扑结构**则不仅涉及单个车道的曲线，还包括整个道路的结构：车道之间如何相互连接、哪些车道允许左转、高速公路的入口位于何处等等。这类结构可以通过有向图来建模，其中交叉点为节点，车道段则为带有属性的边（如限速、车道类型、转弯限制等）。
- 图结构对于路径规划至关重要：规划器不仅需要知道“车道位于何处”，还需要知道“哪条车道顺序才能通往目的地”。

## 语义映射

- 感知并不仅仅意味着在单帧图像中识别物体。随着时间的推移，自主系统会构建出**语义地图**——这是一种对环境的结构化表示，通过多次观测不断积累信息。

- 最简单的形式下，语义地图就是一张二维网格（即**占用网格**），每个单元格都存储着该位置被占用的概率。当机器人移动并使用传感器进行扫描时，它会通过贝叶斯更新来调整这些概率：

$$P(\text{被占用} \mid z_{1:t}) = \frac{P(z_t \mid \text{被占用}) \cdot P(\text{被占用} \mid z_{1:t-1})}{P(z_t)}$$

- 这其实就是贝叶斯定理的应用（见第5章）：每一个新的测量值$z_t$都会更新我们对各个单元格的先验认知。为了避免处理大量小概率值时出现的数值问题，人们通常使用**对数似然**来表示这些概率：

$$l_t = l_{t-1} + \log \frac{P(z_t \mid \text{被占用})}{P(z_t \mid \text{空闲})}$$

- 计算对数似然实际上等同于计算概率的乘积（因为$\log(ab) = \log a + \log b$），如此一来，累积的和就能反映随时间积累的证据。

- 更复杂的语义地图还会为每个单元格赋予语义标签（如道路、人行道、建筑物、植被等），并且可以扩展到三维空间。这类地图与占用网络密切相关，但更注重信息的持久性以及时间上的累积，而非仅基于单帧图像的预测。

- **SLAM**（同时定位与建图），详见第8章，是一种能够在建立地图的同时确定机器人位置的技术。视觉惯性SLAM结合了相机数据和惯性测量单元的数据；而激光SLAM则利用点云匹配技术。感知模块会将检测结果和深度估计值输入到SLAM系统中，后者则负责维护全局地图。

- 现代方法越来越多地使用神经网络带来的隐式表示方式（如第8章中提到的NeRF），以此构建密集且逼真的三维地图，从而可以在任意三维点上获取相关信息。这类神经网络将整个场景的压缩表示存储在网络权重中，从而实现新视图生成以及详细的空间查询等功能。

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Grid setup: 50x50 cells, each 0.2m
grid_size = 50
log_odds = jnp.zeros((grid_size, grid_size))

# Sensor model: log-odds update values
l_occ = 0.85   # confidence that a hit means occupied
l_free = -0.4  # confidence that a pass-through means free

# Simulated obstacle: a wall from (5,20) to (5,30) in grid coords
wall_y = jnp.arange(20, 30)

# Robot at (25, 25), scanning outward
robot = jnp.array([25, 25])

for angle_deg in range(0, 360, 5):
    angle = jnp.radians(angle_deg)
    direction = jnp.array([jnp.cos(angle), jnp.sin(angle)])

    for step in range(1, 25):
        cell = (robot + direction * step).astype(int)
        r, c = int(cell[0]), int(cell[1])
        if r < 0 or r >= grid_size or c < 0 or c >= grid_size:
            break

        # Check if this cell is the wall
        is_wall = (r == 5) and (c >= 20) and (c < 30)
        if is_wall:
            log_odds = log_odds.at[r, c].add(l_occ)
            break
        else:
            log_odds = log_odds.at[r, c].add(l_free)

# Convert log-odds to probability
prob = 1.0 / (1.0 + jnp.exp(-log_odds))

plt.figure(figsize=(6, 6))
plt.imshow(prob.T, origin="lower", cmap="RdYlGn_r", vmin=0, vmax=1)
plt.colorbar(label="P(occupied)")
plt.plot(25, 25, "b*", markersize=10, label="Robot")
plt.legend()
plt.title("2D Occupancy Grid from Bayesian Updates")
plt.show()
```

## 机器人学习

_机器人学习弥合了算法与物理动作之间的鸿沟。本文涵盖了运动学、动力学、经典控制、模仿学习、从仿真到现实的迁移、操作、移动以及安全性等内容，这些技术赋予了机器人移动、抓取、行走以及与现实世界交互的能力。_

- 在前几章中，我们研究了如何感知世界（第8章、第11章文件1）以及如何从数据中学习（第6章）。但仅有感知和学习是不够的。机器人必须**行动**：移动机械臂去抓取杯子、在不平坦的地面上行走，或在仓库中导航。这正是机器人学习的用武之地。

- 核心挑战在于物理世界是连续的、高维的、充满接触且容错率极低。图像识别中的分类错误仅会导致标签错误；而机器人控制中的错误则可能造成机器人损坏或物体掉落。两者的后果截然不同。

## 机器人运动学

- **运动学**描述的是运动的几何关系，而不考虑力的作用。机器人手臂是由关节连接的刚性连杆链。每个关节具有一个自由度（DoF）：要么旋转（转动关节），要么滑动（移动关节）。

- 机器人的**构型**是指所有关节角度（或位移）的集合：$\mathbf{q} = [q_1, q_2, \ldots, q_n]^T$。该向量存在于**关节空间**（或构型空间）中，这是一个$n$维空间，每个轴对应一个关节。一个具有6个自由度的机器人手臂拥有6维的构型空间。

![两连杆机器人手臂：关节角$q1$和$q2$通过正运动学决定末端执行器的位置](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/robot_arm_fk.svg)

- **正运动学（FK）**根据关节角度计算末端执行器（“手”）的位置与朝向。这是一个函数$\mathbf{x} = f(\mathbf{q})$，它将关节空间映射到**任务空间**（即末端执行器的三维位置与朝向，也称为笛卡尔空间）。

- 每个关节由一個$4 \times 4$的齐次变换矩阵描述（回忆第2章中的仿射变换）。**Denavit-Hartenberg（DH）约定**用四个数值来参数化每个关节：连杆长度$a$、连杆扭转角$\alpha$、连杆偏移量$d$以及关节角$\theta$。第$i$个关节的变换矩阵为：

$$T_i = \begin{bmatrix} \cos\theta_i & -\sin\theta_i \cos\alpha_i & \sin\theta_i \sin\alpha_i & a_i \cos\theta_i \\ \sin\theta_i & \cos\theta_i \cos\alpha_i & -\cos\theta_i \sin\alpha_i & a_i \sin\theta_i \\ 0 & \sin\alpha_i & \cos\alpha_i & d_i \\ 0 & 0 & 0 & 1 \end{bmatrix}$$

- 完整的正运动学是所有关节变换矩阵的乘积：$T_{0 \to n} = T_1 T_2 \cdots T_n$。这是矩阵乘法，用于串联变换（第2章内容）：每个关节的变换依次作用，从而将坐标系从基座旋转并平移到末端执行器。

- **逆运动学（IK）**则是相反的问题：给定期望的末端执行器姿态$\mathbf{x}^{_}$，寻找关节角度$\mathbf{q}$使得$f(\mathbf{q}) = \mathbf{x}^{_}$。这要困难得多，因为：

- 映射关系是非线性的（涉及正弦和余弦函数）。
- 可能存在多个解（不同的手臂构型可到达同一点）。
- 可能无解（目标点无法触及）。

- 只有针对特定机器人几何结构才能找到解析解。对于一般的机器人，逆运动学需利用**雅可比矩阵**迭代求解。雅可比矩阵$J(\mathbf{q})$描述了关节角度的微小变化与末端执行器位置的微小变化之间的关系（回忆第3章中的雅可比矩阵）：

$$\dot{\mathbf{x}} = J(\mathbf{q}) \dot{\mathbf{q}}$$

- 若要使末端执行器移动一小段距离$\Delta \mathbf{x}$，则需有$\Delta \mathbf{q} = J^{-1} \Delta \mathbf{x}$（当$J$不是方阵时，可使用伪逆$J^+ \Delta \mathbf{x}$）。这一过程不断迭代，直至末端执行器到达目标点，本质上就是将牛顿法（第3章内容）应用于运动学方程。

- 在**奇异点附近**，雅可比矩阵的秩会降低（某些列变得线性相关，正如我们在第2章中所学）。从物理上讲，这意味着机器人会失去一个自由度：无论关节运动多快，末端执行器都无法在特定方向上移动。奇异点附近伪逆矩阵会发散，因此改用阻尼最小二乘法（加入正则化项$\lambda^2 I$）：

$$\Delta \mathbf{q} = J^T(JJ^T + \lambda^2 I)^{-1} \Delta \mathbf{x}$$

## 动力学与控制

- **动力学**引入了力的作用。机器人手臂的运动方程遵循**操纵器方程**：

$$M(\mathbf{q})\ddot{\mathbf{q}} + C(\mathbf{q}, \dot{\mathbf{q}})\dot{\mathbf{q}} + \mathbf{g}(\mathbf{q}) = \boldsymbol{\tau}$$

- 其中，$M(\mathbf{q})$是质量（惯性）矩阵，$C(\mathbf{q}, \dot{\mathbf{q}})$描述科里奥利力与离心力效应，$\mathbf{g}(\mathbf{q})$是重力矢量，而$\boldsymbol{\tau}$则是关节力矩向量（控制输入）。这是一组二阶微分方程，每个关节对应一个方程。

- 质量矩阵$M$始终对称且正定（回忆第2章内容：正定矩阵能保证唯一的最小值，此处确保系统对施加的力矩作出可预测的反应）。

- **PID控制**是机器人领域应用最广泛的控制器。对于每个关节，它根据误差$e(t) = q_{\text{desired}}(t) - q_{\text{actual}}(t)$来计算力矩：

$$\tau(t) = K_p e(t) + K_i \int_0^t e(s) \, ds + K_d \dot{e}(t)$$

- 这三个术语的作用很直观：
- **比例项**（$K_p$）：根据当前误差进行成比例修正。误差越大，修正幅度越大。就像弹簧将关节拉向目标位置。
- **积分项**（$K_i$）：累积过去的误差以消除稳态偏差。如果关节始终未能到达目标位置，积分项会逐渐增大并提供额外的推力。
- **微分项**（$K_d$）：对误差的变化率作出反应，起到阻尼作用。当误差减小时，它会减缓响应速度，防止超调与振荡。

![PID控制器调节：高$K_p$会导致振荡，高$K_d$会使系统反应迟缓，调节良好的PID能快速达到目标](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/pid_response.svg)

- 调节$K_p$、$K_i$、$K_d$需要权衡：过大的$K_p$会引起振荡，过大的$K_d$会使系统反应迟钝，过大的$K_i$则会导致积分饱和（在持续误差存在时积分值无限增长）。

- **模型预测控制（MPC）**能够提前规划。在每个时间步，它都会求解一个优化问题：在有限的时间范围内，在满足动力学模型和约束条件的前提下，找到能使代价函数（如跟踪误差与控制力之和）最小的一系列未来控制指令。仅应用其中的第一个控制指令，然后在下一个时间步重复该过程。

$$\min_{\mathbf{u}_{0:T}} \sum_{t=0}^{T} \left[ \|\mathbf{x}_t - \mathbf{x}_t^*\|_Q^2 + \|\mathbf{u}_t\|_R^2 \right] \quad \text{满足} \quad \mathbf{x}_{t+1} = f(\mathbf{x}_t, \mathbf{u}_t)$$

- 其中$\|\mathbf{x}\|_Q^2 = \mathbf{x}^T Q \mathbf{x}$是利用正定矩阵$Q$（见第2章）定义的加权范数，借此可以对不同的状态误差施加不同的惩罚。MPC天然能够处理各种约束（关节限位、扭矩限制、避障等），因为这些约束直接被纳入优化过程中。

- **阻抗控制**调节的是力与运动之间的关系，而非严格遵循固定轨迹。它并非命令机器人“移动到位置$x$”，而是要求其“表现为以$x$为中心的弹簧-阻尼系统”：

$$F = K_s(\mathbf{x}^{*} - \mathbf{x}) + D(\dot{\mathbf{x}}^{*} - \dot{\mathbf{x}})$$

- 其中$K_s$为刚度矩阵，$D$为阻尼矩阵。这使得机器人具有柔顺性：一旦碰到障碍物，它会顺应而非强行突破。阻抗控制对于插销入孔或向人递送物体等涉及大量接触的任务至关重要。

## 模仿学习

- 我们无需手动设计控制器，而是可以从演示中学习控制策略。由人类执行任务，机器人进行观察，随后通过学习算法提取出相应的策略。这就是**模仿学习**（或基于演示的学习）。

- **行为克隆（BC）**是最简单的方法：将演示数据视为监督学习的数据集。给定专家提供的观测-动作对$\{(\mathbf{o}_t, \mathbf{a}_t)\}$，训练策略$\pi_\theta(\mathbf{a} \mid \mathbf{o})$以根据观测预测专家的动作。这属于常规的监督学习（见第6章）：最小化损失函数：

$$\mathcal{L}(\theta) = \mathbb{E}_{(\mathbf{o}, \mathbf{a}) \sim \mathcal{D}} \left[ \| \pi_\theta(\mathbf{o}) - \mathbf{a} \|^2 \right]$$

![行为克隆中的分布偏移：微小误差不断累积，导致学到的策略偏离专家轨迹](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/distribution_shift_bc.svg)

- 问题在于**分布偏移**（也称**误差累积问题**）。训练时，策略看到的是专家所处的状态；部署后，策略自身产生的微小误差会使其进入专家从未涉足的状态。这些陌生状态会导致更差的动作，进而产生更加陌生的状态，误差便迅速累积。

- 想象一下，你通过观察一位完美的驾驶员来学习开车。由于专家从未出现过轻微偏离的情况，你从未见过那种情况下的后果。一旦你首次出现轻微偏移，便完全不知道如何纠正。

- **DAgger**（数据集聚合）通过迭代来解决这一问题：

1. 用当前数据训练策略。
2. 在环境中运行该策略，收集新的状态。
3. 请专家为这些新状态标注正确的动作。
4. 将新数据加入数据集并重新训练。

- 经过多次迭代，数据集涵盖了策略实际访问的状态，而不仅仅是专家的轨迹。由于策略已经见过并学会如何从自身的错误中恢复，因此其性能得以提升。

- **基于Transformer的动作分块（ACT）**是一种现代方法，策略一次性预测一系列未来动作（“分块”），而非逐个预测。该方法采用以Transformer为骨干的条件变分自编码器实现。预测动作分块更具鲁棒性，因为它能捕捉时间相关性：抓取动作的平滑性被编码在分块中，而不依赖于容易偏离的逐步骤自回归预测。

- **扩散策略**将扩散模型（见第8章）应用于动作生成。它并非预测单个动作，而是建模在给定观测条件下所有可能的动作分布。从噪声出发，通过迭代去噪生成动作序列。这种方法能自然地处理**多模态问题**：当存在多种完成任务的合法方式（从左或右接近目标）时，扩散模型可以同时表示这两种模式，而回归策略则会取平均值（最终落在两者之间的某个位置，可能并不符合实际需求）。

## 仿真到现实的迁移

- 在现实世界中训练机器人成本高昂、速度缓慢且充满危险。机器人若通过试错学习抓取，可能需要数千次尝试，期间还会损坏物体乃至自身。**仿真**则提供了无限、安全且快速的训练环境。但仿真器并不完美：物理规律被近似处理，视觉信息为人造，接触模型也被简化。
- **仿真到现实差距**指的是仿真环境与真实环境之间的性能差异。在仿真中表现完美的策略，在真实机器人上可能会完全失效，因为它过度适应了仿真器特有的细节。

![通过域随机化实现仿真到现实迁移：在多种随机化仿真环境中训练，使现实世界只是其中的另一种变体](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/sim_to_real.svg)

- **域随机化**通过在广泛的仿真设置下进行训练来应对这一问题。与其使用单一仿真环境，不如使用成千上万种随机化的仿真环境，包括：
- 物理属性：摩擦系数、质量、阻尼；
- 视觉属性：光照、纹理、颜色、摄像头位置；
- 动力学属性：电机延迟、噪声水平。

- 其原理是：如果策略能适应所有这些变化，那么现实世界就只是该分布中的“另一种变体”。策略会学到对随机化属性具有不变性的特征，而这些不变特征能够顺利迁移。

- **系统辨识**采取相反的做法：不随机化所有参数，而是仔细测量真实系统的物理参数，并调整仿真器以匹配这些参数。这种方式能提供更精确的仿真结果，但较为脆弱（任何未被建模的效应都会导致误差）。

- 实践中，最佳方案是结合两者：先通过系统辨识让仿真器尽可能接近真实情况，再通过域随机化来覆盖剩余的不确定性。

- **通过微调实现仿真到现实迁移**：主要在仿真环境中训练，随后在现实世界中进行少量微调。仿真提供了良好的初始状态，而现实数据则用于修正仿真器特有的偏差。这种方式所需的现实数据远少于从头开始训练。

## 机器人的世界模型

- 上述所有强化学习和模仿学习方法都是**无模型**的：策略通过直接交互（或演示）来学习如何行动，而不显式建模世界的工作原理。另一种方法是**基于模型**的学习：先学习环境的动力学模型，再利用该模型进行规划或生成合成经验。

- **世界模型**学习状态转移函数 $p(s_{t+1} \mid s_t, a_t)$：给定当前状态和动作，预测下一个状态（如第10章所述）。在机器人领域，这意味着预测机器人执行特定动作后会发生什么：“如果我向左推动这个方块，它会滑动3厘米，后面的杯子就会倾倒。”

- 其优势在于**样本效率**。与真实世界的机器人交互成本很高。如果机器人能从少量真实数据中学会世界模型，它就能在脑海中“模拟”出成千上万条轨迹，从而在不接触物理世界的情况下规划并优化策略。这类似于棋手通过心算来预判后续走法。

- **DreamerV3**是一种通用的基于模型的强化学习智能体。它同时学习三个组件：
- **表征模型**：将观测数据编码为紧凑的隐状态；
- **转移模型**（即世界模型）：根据当前状态和动作预测下一个隐状态；
- **奖励模型**：根据隐状态预测奖励。

- 该智能体通过在隐空间中运行转移模型来“做梦”，在这些想象出的轨迹上训练策略，再将策略迁移到真实环境中。关键创新在于所有想象过程都在隐空间（紧凑的学习表征）中进行，而非像素空间，从而在计算上可行。

$$\hat{s}_{t+1} = f_\theta(s_t, a_t), \quad \hat{r}_t = g_\theta(s_t)$$

- 转移模型 $f_\theta$ 和奖励模型 $g_\theta$ 基于真实经验进行训练，而策略则在想象出的轨迹上训练。这样便将数据采集与策略优化分离开来。

- 对于机器人操作而言，世界模型能够实现**心理预演**。在尝试抓取之前，机器人可以在学到的模型中模拟多种抓取方式，并选择最有可能成功的一种。这对于接触复杂的任务尤其重要，因为现实中的试错既缓慢又充满风险。

- 世界模型也与**仿真到现实迁移**自然契合：基于真实数据训练的世界模型实际上就是一个能自动捕捉真实物理规律的学习型仿真器，从而完全绕开仿真到现实差距。虽然对于已知场景而言，它可能不如手工构建的仿真器精确，但它能准确捕捉手工仿真器常常出错的效果（如摩擦、变形、接触动力学）。

- **JEPA**（联合嵌入预测架构，见第10章）提供了一种替代像素级预测的方案。JEPA不在像素层面预测未来观测，而是在嵌入空间中进行预测：“下一个状态的隐表征会接近这个向量。”这种方式避免了预测像素级精确结果的难题（既没必要又浪费计算资源），专注于预测对决策至关重要的未来信息。

- 世界模型的局限性在于**预测误差累积**。转移模型中的微小误差会在长时间模拟中不断累积，导致想象出的轨迹偏离现实。解决办法包括缩短想象时长、使用集成模型（利用不确定性检测预测何时不可靠），以及定期用新的真实数据对模型进行校准。

## 操作

- **操作**是指利用机器人的末端执行器与物体互动的技术：抓取、放置、推动、插入、组装等。

- **抓取**是最基础的操作技能。其目标是找到稳定的抓取姿态：即夹持器能够牢固握住物体的位置和方向。
- **解析式抓取规划**利用物理学原理。如果接触力能够抵抗外部力矩（力和扭矩），则抓取就是稳定的。对于平行夹爪而言，最简单的判据是**力闭合**条件：接触面的法线必须能覆盖所有受力方向，这样抓取才能抵御任何干扰。这涉及到对抓取力矩矩阵的秩进行检验，这也是第2章中秩概念的直接应用。

- **数据驱动的抓取**通过传感器输入来学习预测抓取成功与否。给定桌面上物体的深度图像后，神经网络会为每个候选夹持器姿态预测一个抓取质量评分。**GraspNet**及类似架构采用点云编码器（如PointNet风格，见第8章）来预测具有置信度的6自由度抓取姿态（位置+朝向）。

- **灵巧操作**超越了简单的拾取与放置。多指手部拥有20个以上的自由度，能够执行诸如手指间旋转物体、使用工具以及精细装配等任务。由于状态空间极其庞大且接触关系复杂，这成为机器人领域最棘手的问题之一。

- 学习灵巧操作通常采用强化学习（见第6章），在仿真环境中进行大量域随机化处理。OpenAI利用Shadow手解决魔方问题的研究中，在仿真环境中通过随机化物理参数训练PPO策略，最终成功迁移到真实的机器人手上。

- **富含接触的任务**，如插销插入孔中或擦拭表面，要求机器人与环境保持可控的接触。这类任务需要力感知与柔顺控制（阻抗控制），由于接触物理难以建模，因此很难在仿真中精确模拟。

## 运动控制

- 运动控制是指让机器人的身体在世界中移动：行走、奔跑、攀爬、游泳。它与操作的主要区别在于，机器人在移动时必须保持平衡，且与地面的接触点会随时间变化。

- **足式运动**极具挑战性，因为它本质上是不稳定的。双足机器人（人形机器人）在单腿站立阶段类似于倒立摆。其质心必须位于支撑多边形（与地面接触的脚所形成的凸包）之内，否则机器人就会摔倒。

- **零力矩点（ZMP）**是指地面上重力和惯性力产生的净力矩为零的点。只要ZMP保持在支撑多边形内，机器人就不会倾倒。传统的人形机器人控制器（如本田的ASIMO）会规划使ZMP始终处于限定范围内的轨迹。

- **中枢模式发生器（CPG）**是一种受生物学启发的基于振荡器的控制器。动物依靠脊髓中的神经回路产生有节奏的运动模式（行走、小跑、疾驰），无需大脑持续参与。CPG模型使用耦合微分方程来描述：

$$\dot{\phi}_i = \omega_i + \sum_j w_{ij} \sin(\phi_j - \phi_i - \psi_{ij})$$

其中，$\phi_i$ 是振荡器$i$的相位，$\omega_i$ 是其自然频率，$w_{ij}$ 为耦合强度，$\psi_{ij}$ 为期望的相位偏移。不同的相位关系会产生不同的步态：所有腿同步（跳跃）、成对交替（小跑）、依次摆动（行走）。正弦耦合机制能自然使振荡器同步，这与傅里叶级数（见第3章）将运动分解为频率成分的原理类似。

- **用于运动控制的强化学习**已成为敏捷四足及人形机器人的主流方法。机器人在仿真环境中通过试错学习策略$\pi(\mathbf{a} \mid \mathbf{o})$（见第6章），奖励项包括前进速度、稳定性和能量效率，惩罚项则针对摔倒、关节超限以及动作生硬等情况。

- 近期研究（如Agility Robotics、波士顿动力公司及学术实验室的成果）表明，经RL训练得到的运动策略远比手工设计的控制器更为稳健。它们能自然学会从外力推搡中恢复、适应地形变化，并能应对工程师未曾预料的情况。训练通常采用PPO算法（见第6章）并结合域随机化技术。

- **四足机器人**（如波士顿动力的Spot或宇树科技的Go2）已成为足式机器人的主力。四条腿提供了固有的稳定性（三条腿构成的三角支撑结构总能承受身体重量，同时另一条腿可自由移动）。四足机器人的RL策略取得了令人瞩目的成果：能以3米/秒以上的速度奔跑、爬楼梯、在崎岖地形中导航，并能从踢击中恢复。

- **人形机器人运动**更为困难，因为双足机器人的支撑多边形较小且质心较高。近期进展（如特斯拉Optimus、Figure、宇树H1）采用在仿真中训练并精心设计奖励函数的方法。人形机器人不仅要学会行走，还要协调手臂摆动以保持平衡、应对不平坦路面，并能从扰动中恢复。

## 机器人学习中的安全性

- 为了学习而随机探索的机器人（如RL中的情况）可能会损坏自身、周围环境或附近的人类。**安全的机器人学习**会对探索过程加以限制，以避免灾难性后果。

- **受限强化学习**在MDP中加入了安全约束（见第6章）。目标变为：在满足$J_c(\pi) \leq d$的条件下最大化奖励，其中$J_c$为预期的累积成本（如碰撞事件），$d$为允许的最大成本。像受限策略优化（CPO）这样的算法对PPO进行了扩展，以处理这些约束。

- **安全边界**定义了机器人绝对不能逾越的硬性界限，无论学习到的策略如何指示。安全控制器会监测机器人的状态，一旦即将违反约束（如接近关节极限、在人类附近移动过快或超过力阈值），便会覆盖学习到的策略。这是一种分层架构：学习算法负责性能优化，而安全层则负责约束管理。
- **风险感知规划**会显式地对环境中的不确定性以及机器人自身的状态估计进行建模。它并非针对最有可能出现的结果进行规划，而是基于置信区间来规划最坏情况。这与条件数概念相关（第2章）：条件良好的系统对扰动具有鲁棒性，而风险感知规划旨在寻找在受到扰动时仍能保持安全的控制策略。

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

def forward_kinematics(q1, q2, l1=1.0, l2=0.8):
    """Compute joint and end-effector positions for a 2-link arm."""
    x1 = l1 * jnp.cos(q1)
    y1 = l1 * jnp.sin(q1)
    x2 = x1 + l2 * jnp.cos(q1 + q2)
    y2 = y1 + l2 * jnp.sin(q1 + q2)
    return jnp.array([0, x1, x2]), jnp.array([0, y1, y2])

fig, ax = plt.subplots(figsize=(6, 6))
configs = [(0.5, 0.3), (1.0, -0.5), (1.5, 1.0), (2.0, -1.5)]
colors = ["#e74c3c", "#3498db", "#27ae60", "#9b59b6"]

for (q1, q2), c in zip(configs, colors):
    xs, ys = forward_kinematics(q1, q2)
    ax.plot(xs, ys, "o-", color=c, linewidth=2, markersize=6,
            label=f"q=({q1:.1f}, {q2:.1f})")

ax.set_xlim(-2, 2); ax.set_ylim(-2, 2)
ax.set_aspect("equal"); ax.grid(True); ax.legend()
ax.set_title("2-Link Robot Arm: Forward Kinematics")
```

1. 利用雅可比伪逆实现逆运动学。从随机配置出发，迭代地将末端执行器移动到目标位置。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

l1, l2 = 1.0, 0.8

def end_effector(q):
    x = l1 * jnp.cos(q[0]) + l2 * jnp.cos(q[0] + q[1])
    y = l1 * jnp.sin(q[0]) + l2 * jnp.sin(q[0] + q[1])
    return jnp.array([x, y])

jacobian_fn = jax.jacobian(end_effector)

target = jnp.array([0.5, 1.2])
q = jnp.array([0.1, 0.1])
trajectory = [end_effector(q)]

for _ in range(50):
    pos = end_effector(q)
    error = target - pos
    if jnp.linalg.norm(error) < 1e-4:
        break
    J = jacobian_fn(q)
    # Damped pseudo-inverse to handle near-singularities
    dq = J.T @ jnp.linalg.solve(J @ J.T + 0.01 * jnp.eye(2), error)
    q = q + dq
    trajectory.append(end_effector(q))

traj = jnp.stack(trajectory)
plt.plot(traj[:, 0], traj[:, 1], "b.-", label="end-effector path")
plt.plot(*target, "r*", markersize=15, label="target")
plt.gca().set_aspect("equal"); plt.grid(True); plt.legend()
plt.title(f"IK converged in {len(trajectory)-1} steps")
plt.show()
```

1. 模拟一个简单的PID控制器来跟踪期望的关节轨迹。观察调整增益所产生的效果。

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Desired trajectory: smooth sinusoidal motion
dt = 0.01
t = jnp.arange(0, 5, dt)
q_desired = jnp.sin(2 * t)

# Simulate second-order dynamics: m * q_ddot + b * q_dot = tau
m, b_damp = 1.0, 0.5

for Kp, Kd, Ki, label in [(10, 5, 0, "PD only"), (10, 5, 2, "PID"), (50, 10, 2, "Aggressive PID")]:
    q, q_dot, integral = 0.0, 0.0, 0.0
    qs = []
    for i in range(len(t)):
        error = q_desired[i] - q
        integral += error * dt
        d_error = -q_dot  # derivative of error (desired velocity is known but simplified here)
        tau = Kp * error + Kd * d_error + Ki * integral
        q_ddot = (tau - b_damp * q_dot) / m
        q_dot += q_ddot * dt
        q += q_dot * dt
        qs.append(float(q))

    plt.plot(t, qs, label=label)

plt.plot(t, q_desired, "k--", label="desired", linewidth=2)
plt.xlabel("Time (s)"); plt.ylabel("Joint angle")
plt.legend(); plt.title("PID Controller Tracking")
plt.show()
```

## 视觉-语言-动作模型

_视觉-语言-动作模型（VLAs）将视觉感知、语言理解与动作执行整合到一个神经网络中。本文件介绍了VLAs的架构、动作令牌化方法、RT-2、Octo、OpenVLA等模型，以及相关的预训练策略、泛化能力、与具体硬件无关的模型设计，还有相应的评估标准。_

- 在之前的文档中，我们讨论了感知功能（对世界的感知）以及机器人学习功能（对机器人的控制）。传统上，这些功能是分开处理的：感知模块负责检测物体，语言模块负责解析指令，而控制模块则负责生成动作。每个模块都是独立设计、训练和调试的。

- **视觉-语言-动作模型（VLAs）**则将这一流程整合到一个神经网络中。该模型接收图像（视觉信息）和自然语言指令（语言信息），并输出动作指令（即机器人的实际动作）。整个过程由一个模型端到端完成。

- 这与第10章中提到的统一趋势一致：正如多模态模型将视觉理解和语言理解整合到同一架构中一样，VLAs则进一步将这一理念扩展到物理动作的生成上。其核心思想在于，语言为任务描述提供了自然且灵活的接口（例如“拿起红色的杯子并将其放在架子上”），而那些经过预训练的大型视觉-语言模型已经能够同时理解图像和指令。

## 从视觉-语言到动作

- 回想一下第10章的内容，像LLaVA和Flamingo这样的**视觉-语言模型（VLMs）**以图像和文本作为输入，输出文本结果。它们能够理解场景、回答问题，并以语言形式执行指令。

- 而VLAs则提出了这样一个问题：如果输出的不是文本，而是**机器人的动作**会怎样？这类模型不会生成“红色杯子在桌子的左侧”这样的文字描述，而是会生成一系列动作指令，让机器人动手去拿起那个杯子。

- 其核心的架构思路是：动作也可以像单词一样被表示为令牌。如果VLM是通过逐个预测下一个令牌来生成文本的，那么VLAs则是以相同的方式生成动作令牌。Transformer模型本身并不关心输出的令牌代表的是“杯子”还是“将夹持器向前移动2厘米”。

- 这种思路将机器人控制问题转化为序列建模问题，而Transformer模型在这方面具有很强的优势（见第7章）。模型会学习到这样的映射关系：（图像观测结果、语言指令）$\to$（动作令牌序列）。

## VLA的架构

![VLA架构：摄像头拍摄的图像和语言指令会被编码为令牌，再由大型语言模型处理，最终解码为机器人的动作](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/vla_architecture.svg)

- 一个典型的VLA包含三个组成部分：

- **视觉编码器**：负责将摄像头拍摄的图像转换为视觉令牌。通常使用经过预训练的ViT模型（见第8章）或SigLIP编码器（见第10章）。图像会被分割成多个小块，每个小块都被转换为一个令牌，这一过程与标准的视觉Transformer模型类似。

- **语言模型核心**：即经过预训练的大型语言模型（如LLaMA、PaLM），它负责处理那些交替出现的视觉令牌和语言令牌序列。正是在这里，模型通过结合指令内容和视觉特征来理解“拿起**红色**的杯子”这样的指令。

- **动作输出模块**：负责将大型语言模型的输出转换为机器人的实际动作。它可以是一个简单的多层感知机，将模型的最后隐藏状态转换为连续的动作值；也可以是某种令牌化机制，将动作转换为由大型语言模型所掌握的词汇表中的离散令牌。

- 其架构结构如下：

$$\text{图像} \xrightarrow{\text{ViT}} \text{视觉令牌} \quad + \quad \text{指令} \xrightarrow{\text{令牌化器}} \text{语言令牌} \quad \xrightarrow{\text{大型语言模型}} \quad \text{动作令牌}$$

- 视觉令牌和语言令牌会被拼接在一起（或交替排列），然后输入到Transformer核心模型中，该模型会通过自回归方式生成动作令牌。这一架构与VLM的架构类似（见第10章），只不过VLA的输出形式是动作而非文本。

## 动作令牌化

- 机器人的动作是连续的，比如关节速度、末端执行器的位置、夹持器的宽度等。为了让大型语言模型能够处理这些数据，必须先将它们转换为离散的令牌。

![动作令牌化：连续的动作值会被划分成若干离散的区间，大型语言模型则将这些区间作为令牌来生成](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/action_tokenisation.svg)

- 最简单的方法是**均匀离散化**。将每个动作维度划分为$N$个区间，覆盖该维度所有可能的取值范围。例如，如果x轴方向的速度范围是-0.1到0.1米/秒，且我们使用256个区间，那么每个区间的长度约为$\frac{0.2}{256} \approx 0.8$毫米/秒。某个动作值会被映射到最接近的区间编号，该编号就成为了一个令牌。

- 如果有7个动作维度（6个自由度加上夹持器），并且每个维度都使用256个区间，那么总共会有$7 \times 256 = 1792$个动作令牌。这些令牌会被添加到大型语言模型现有的文本令牌库中。模型会像生成文本单词一样，逐个维度地自回归地生成动作令牌。

- **动作分块**则是一种更高级的方法，它一次预测多个未来的时间步，而不仅仅是一个动作。如果分块大小为$H$，那么模型就会输出$H \times d$个令牌（其中$d$是动作维度的数量）。这对于实现流畅、连贯的动作非常重要。因为如果每次只预测一步，由于每次预测都是独立的，所以动作可能会显得很生硬。而分块机制则迫使模型规划出一段较短的轨迹，从而体现动作的时间结构。

- 更复杂的做法是使用**基于VQ-VAE的 learned令牌化方法**（见第10章）。VQ-VAE编码器会将一系列连续的动作转换为一系列离散的代码本索引，而解码器则根据这些索引来重建连续的动作。这样一来，大型语言模型生成的就不是均匀划分后的数值，而是代码本索引。这一原理与图像令牌化技术类似（见第10章），后者也是将视觉信息压缩为紧凑的离散代码。

## 主要的VLA模型

- **RT-2**（Robotic Transformer 2，谷歌DeepMind开发）是首个大规模的视觉-语言-动作模型。它以预训练好的视觉语言模型（PaLM-E或PaLI-X，参数量可达550亿）为基础，再通过机器人演示数据对其进行微调。动作以文本字符串的形式表示：序列“1 128 91 241 5 101 127”对应一个7维的动作向量（每个数字都是一个二进制索引）。

- RT-2展现出一项显著特性：视觉语言模型中的能力可以迁移至机器人控制领域。该模型能够执行那些在训练数据中从未出现过的指令（例如，“把香蕉放到以A开头的那个地方”，这需要视觉物体识别、世界知识以及动作规划能力）。视觉语言模型的语言理解和视觉推理能力因此得以“免费使用”。

- RT-2的局限性在于它是在某种特定结构的机器人数据上训练的（即带有特定夹持器的机械臂），因此无法泛化到其他类型的机器人上。

- **Octo**（加州大学伯克利分校开发）是一种开源的、与机器人具体结构无关的视觉-语言-动作模型，旨在适用于不同的机器人平台。其核心创新点包括：

- 采用**扩散式动作生成机制**，而非传统的自回归式token预测方式。该机制利用变换器的输出，通过去噪扩散过程来生成动作（详见第8章）。这种方式能够自然地处理多模态动作分布——即完成某项任务可能存在多种有效方法。

```text
![多模态动作分布：回归算法会将两条有效路径通过障碍物合并为一条无效路径](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/multimodal_action_distribution.svg)
```

- **灵活的观测与动作空间**：Octo会根据不同机器人的结构特点使用相应的token化器。它是在Open X-Embodiment数据集上预训练的，该数据集包含了22种不同机器人模型的演示数据。

- **高效的微调方式**：仅需100个演示样本，Octo就能适配新的机器人模型，这使得数据量有限的实验室也能轻松使用它。

- **OpenVLA**（斯坦福大学和加州大学伯克利分校共同开发）则是通过微调现有的开源视觉语言模型（基于Llama架构）来实现机器人功能。该模型采用70亿参数的架构，对动作进行统一token化处理（每维256个等级），并在Open X-Embodiment数据集上进行训练。它的优势在于结构简单：整体架构仍是标准的视觉语言模型，只需在词汇表中添加动作相关的token即可，因此便于利用现有的大型语言模型基础设施进行训练和部署。

- **$\pi_0$**（Physical Intelligence团队开发）代表了当前最先进的视觉-语言-动作模型。它同样基于预训练的视觉语言模型架构，但采用了**流匹配式动作生成机制**（详见第8章）。该机制通过学习速度场将噪声转化为动作分布，从而生成平滑且连贯的动作轨迹。$\pi_0$展现了出色的通用性，能够在多种机器人模型上执行任务，包括双臂操作和精细手部控制等。

## 预训练方法

- 视觉-语言-动作模型从预训练好的视觉语言模型中受益匪浅，因为后者已经具备理解视觉场景和语言的能力。典型的预训练流程包括以下步骤：

1. **视觉语言模型预训练**：利用互联网上的数十亿张图像-文本对来训练视觉语言模型（如CLIP、SigLIP，或是第10章中介绍的LLaVA风格训练方法）。

2. **机器人数据协同训练**：将互联网数据与机器人演示数据混合后，对视觉语言模型进行微调。互联网数据有助于避免模型遗忘视觉和语言理解能力，而机器人数据则用于教授动作生成技巧。两种数据的混合比例很重要：机器人数据过多会削弱语言理解能力，而过少则无法让模型学会动作生成。

3. **针对特定任务的微调**：可根据具体任务或机器人类型，进一步对模型进行微调，通常会采用LoRA技术（详见第10章），以减少需要训练的参数数量。

- 机器人相关的数据量远远少于互联网数据。虽然视觉语言模型可能已经在数十亿张图像上完成预训练，但最大的机器人数据集（如Open X-Embodiment）也仅包含数百万帧图像。正是由于数据稀缺，才必须从预训练好的视觉语言模型开始：视觉和语言相关的表征能力可以直接迁移过来，只需从有限的机器人数据中学习动作映射关系即可。

## 泛化能力

- 视觉-语言-动作模型的核心优势在于**泛化能力**：即能够在训练时未曾见过的环境中，处理从未见过的物体，执行从未见过的指令。

- 视觉-语言-动作模型在多个方面具备泛化能力：

- **新物体**：由于在互联网数据上进行了预训练，视觉语言模型能够识别各种物体。如果模型从网络图片中知道“螺丝刀”的样子，那么即使没有任何关于使用螺丝刀的机器人演示数据，它也能操控螺丝刀。

- **新指令**：凭借组合式语言理解能力，模型能够理解由已知概念构成的新指令。例如，即使训练数据中只有红色积木的堆叠示例，模型也能理解“把蓝色积木堆在绿色积块上”这样的指令，因为它从语言预训练中掌握了颜色形容词的含义。

- **新环境**：在一定程度上，视觉-语言-动作模型能够在不同的视觉场景下进行泛化（如不同的桌面、照明条件、背景等），因为视觉编码器已经在各种网络图片上完成了预训练。不过这种泛化能力也存在局限：在实验室中训练出的机器人可能在杂乱的厨房环境中表现不佳。

- **不同结构的机器人**：这是最具挑战性的泛化方向。不同机器人具有不同的动作空间（关节角度与末端执行器速度）、不同的传感器（手腕摄像头与顶部摄像头）以及不同的物理性能。像Octo和$\pi_0$这类与机器人结构无关的模型，通过灵活的token化器以及针对多种机器人类型的预训练，来克服这一难题。

- 泛化能力的评估是通过**未见过的任务**来进行的：让机器人执行那些它从未接受过训练的任务。如果在这些新任务上，模型的成功率能达到50%–80%，就已经属于相当不错的成绩了；而对于那些属于训练数据范围内的任务，其成功率通常可超过90%。随着模型性能的提升以及机器人数据集的扩大，这一差距正在逐渐缩小。

## 与机器人结构无关的模型

- 该领域正朝着“一个模型，多台机器人”的方向发展。无需为每台机器人单独训练策略，只需一个VLA模型即可控制多台机器人。

- 这就需要解决**动作空间不匹配**的问题。具有并联式夹具的7自由度机械臂有7个动作维度，双臂结构则有14个维度，四足机器人有12个维度，而人形机器人则超过30个维度。因此，动作编码方式必须具备足够的灵活性，才能应对所有这些情况。

- 相关解决方案包括：
- **填充式动作向量**：以最大的动作空间作为标准，用零值填充较小的动作空间。
- **针对不同机器人的独立动作处理模块**：使用共享的Transformer架构，再为每种机器人类型配备独立的小型MLP。
- **标准化动作表示**：将所有动作统一表示在同一个框架中（例如以世界坐标系中的末端执行器速度来表示），这样具有相似动作行为的不同机器人就可以使用相同的动作编码。

- 共享的Transformer架构负责学习通用的视觉与语言理解能力，以及常见的操作策略（从上方接近物体、调整位置以对准物体、闭合夹具等）。而针对特定机器人的组件则只需将这些高级策略转化为具体的电机指令即可。

## 测试与评估

- 对视觉-语言-动作模型进行评估极具挑战性，因为这需要借助实体机器人进行实验，或者使用高精度的仿真环境。

- **SIMPLER**（用于机器人学习的仿真操作策略评估工具）提供了标准化的仿真环境，无需实体硬件即可比较不同VLA模型的性能。其评估结果与现实世界中的表现高度相关，且能够实现可重复的测试。

- **现实世界测试**仍然是最权威的评估方式。典型的测试流程如下：

1. 设定一系列具有明确成功标准的任务（如物体到达目标位置、选中了正确的物体、在规定时间内完成任务等）。
2. 每个任务进行$N$次试验（通常为10–50次）。
3. 报告成功率及置信区间。
4. 引入从未被用于训练的任务，以评估模型的泛化能力。

- **Open X-Embodiment**数据集和评估标准汇集了来自22家机构的多种机器人平台上的数据。它提供了标准化的格式用于分享实验结果，同时也提供了统一的评估方法，便于跨不同机器人平台进行模型迁移测试。

1. 实现动作编码功能：将连续的动作值离散化为不同的区间，然后再将其还原。同时观察不同区间数量对量化误差的影响。

```python
import jax.numpy as jnp

# Continuous action: 7 dimensions (6 DoF + gripper)
action_true = jnp.array([0.023, -0.051, 0.012, 0.1, -0.03, 0.005, 0.8])
action_min = jnp.array([-0.1, -0.1, -0.1, -0.5, -0.5, -0.5, 0.0])
action_max = jnp.array([ 0.1,  0.1,  0.1,  0.5,  0.5,  0.5, 1.0])

for n_bins in [16, 64, 256, 1024]:
    # Tokenise: map continuous value to bin index
    normalised = (action_true - action_min) / (action_max - action_min)
    tokens = jnp.clip((normalised * n_bins).astype(int), 0, n_bins - 1)

    # Detokenise: map bin index back to continuous value
    reconstructed = (tokens + 0.5) / n_bins * (action_max - action_min) + action_min

    error = jnp.linalg.norm(action_true - reconstructed)
    print(f"bins={n_bins:4d}  tokens={tokens}  error={error:.6f}")
```

1. 比较动作分块预测与单步预测的效果。生成平滑的轨迹，为单步预测结果添加噪声，然后与基于动作分块的预测方法进行比较。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Ground truth smooth trajectory (e.g., reaching motion)
t = jnp.linspace(0, 2 * jnp.pi, 100)
gt_x = jnp.sin(t)
gt_y = 1 - jnp.cos(t)

# Single-step: each prediction has independent noise
rng = jax.random.PRNGKey(42)
noise_ss = jax.random.normal(rng, (100, 2)) * 0.05
single_step = jnp.stack([gt_x, gt_y], axis=1) + noise_ss
# Cumulative drift from single-step errors
single_step_cumulative = jnp.cumsum(noise_ss, axis=0) * 0.3 + jnp.stack([gt_x, gt_y], axis=1)

# Chunked (chunk_size=10): noise is correlated within chunks, smoother
chunk_size = 10
rng2 = jax.random.PRNGKey(7)
chunks = []
for i in range(0, 100, chunk_size):
    chunk_noise = jax.random.normal(jax.random.fold_in(rng2, i), (2,)) * 0.05
    chunk = jnp.stack([gt_x[i:i+chunk_size], gt_y[i:i+chunk_size]], axis=1)
    chunks.append(chunk + chunk_noise)
chunked = jnp.concatenate(chunks, axis=0)

plt.figure(figsize=(8, 4))
plt.plot(gt_x, gt_y, "k-", linewidth=2, label="Ground truth")
plt.plot(single_step_cumulative[:, 0], single_step_cumulative[:, 1],
         "r-", alpha=0.7, label="Single-step (drifts)")
plt.plot(chunked[:, 0], chunked[:, 1], "b-", alpha=0.7, label="Chunked (stable)")
plt.legend(); plt.axis("equal"); plt.grid(True)
plt.title("Action Chunking vs Single-Step Prediction")
plt.show()
```

```python
# Regression predicts the mean = average of modes (invalid!)
mean_pred = samples.mean(axis=0)
```

## 自动驾驶汽车

_自动驾驶汽车是商业化程度最高的自主系统，它将感知、预测、规划与控制功能集成在同一辆车上。本文件涵盖了自动驾驶系统的各组成部分、高精度地图、运动预测、路径规划、端到端驾驶流程、仿真技术、安全标准以及自主驾驶的等级。_

- 自动驾驶汽车可以说是目前最难以解决的机器人技术难题之一。与在受控环境中工作的工厂机器人不同，自动驾驶汽车必须应对复杂的现实环境：行为难以预测的驾驶员、乱穿马路的行人、夜间突然出现的施工区域，以及不断变化的天气状况。

- 其面临的挑战也极为严峻。自动驾驶汽车需要在高速公路上以高速行驶，同时还要与那些容易受到伤害的道路使用者共处。对于那些可能危及安全的故障，其容错率几乎为零。

## 自动驾驶系统的架构

- 传统的自动驾驶系统采用**模块化架构**，由四个阶段组成，每个阶段的结果都会传递给下一个阶段：

$$\text{感知} \to \text{预测} \to \text{规划} \to \text{控制}$$

![自动驾驶系统架构：传感器负责数据感知，再由感知模块进行预测、规划，最终实现车辆控制](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/autonomous_driving_stack.svg)

- **感知阶段**（详见本章第一份文档）负责将原始传感器数据处理成结构化的场景信息：包括具有三维位置、速度和类别标签的物体信息、车道标记、交通信号灯以及可行驶区域的边界信息。

- **预测阶段**则用于预测其他道路使用者（车辆、行人、骑自行车的人等）未来的移动方向。根据当前场景状况，该模块会为每个对象输出未来一段时间内的行进轨迹（通常为3到8秒后）。

- **规划阶段**负责决定车辆应采取的行动：选择哪条路线行驶、何时变道、何时让行、何时加速或刹车。它基于预测得到的场景信息，为车辆生成一条既安全又舒适、且能帮助其更快到达目的地的行进路径。

- **控制阶段**则负责将规划好的路径转化为具体的控制指令：转向角度、油门深度和刹车力度。这是最低层的环节，负责将抽象的路径信息转化为实际的车辆动作。

- 这种模块化设计具有明显的工程优势：各个模块可以独立开发、测试和改进。但同时也存在一些缺点：错误会逐级传递下去（如果某个物体未被检测到，规划模块就无法获取相关信息），而且在不同接口之间信息也会丢失（规划模块只能看到物体的边界框，而无法看到生成这些边界框的原始传感器数据）。

## 高精度地图

- **高精度地图**是一种细节丰富、精确度可达厘米级的数字地图，它能够记录道路的各类结构信息：车道边界、车道之间的连接关系、交通标志的位置、限速信息、人行横道的位置以及道路表面的高度信息。

- 高精度地图为自动驾驶任务提供了有力的基础支持。感知模块无需每帧都重新识别车道边界，只需确定车辆在地图中的位置，并确认实际场景与地图上的信息一致即可。这大大简化了路径规划的工作。

- 制作高精度地图需要使用配备有高端激光雷达、摄像头以及RTK-GPS技术的专用测绘车辆。随着道路状况的变化，这些地图也需要定期维护和更新。这一过程成本高昂，而且难以覆盖地球上的所有道路。

- **无地图驾驶**（也称为“在线绘图”）旨在消除对预先制作好的高精度地图的依赖。在这种方式下，车辆会利用自身的传感器实时构建本地地图。像**MapTR**和**MapTRv2**这样的模型则采用变换器架构，直接从摄像头图像中预测出车道中心线、道路边界、人行横道等地图元素，并以有序的点序列形式输出结果。

- 无地图驾驶方法虽然牺牲了地图的精确度，但却提升了系统的可扩展性：只要车辆能够行驶的任何道路，它都可以被映射出来。不过，这就要求感知系统具备足够的强大功能，能够实时识别出所有相关的道路结构，尤其是在复杂的交叉路口、高速公路匝道以及施工区域中。

- 在实际应用中，许多系统采用混合式方法：先使用来自现有地图提供商的、包含粗略道路拓扑结构的轻量级地图，然后再通过车辆的传感器实时补充详细信息。

## 运动预测

- 预测其他道路使用者的移动方向是自动驾驶领域中最困难的子问题之一。人类的行为难以预测，他们的意图也不易察觉，而且可能的未来发展路径数量极其庞大。

- 预测模型的输入是**场景上下文信息**：即最近一段时间内所有被检测到的道路使用者的位置和速度信息（通常为1到2秒内的数据），再加上一些静态信息，如车道几何形状、交通信号灯、道路边界等。

- 模型的输出则是每个道路使用者未来一段时间内的**预测轨迹**，通常为3到8秒后的情况。由于未来具有不确定性，优秀的预测模型会输出多条可能的轨迹，并为每条轨迹赋予相应的概率值，而非仅给出一个单一的预测值。

- **轨迹预测**可以被视作一种回归问题：即预测每个道路使用者在未来的各个时间点上的$(x, y)$坐标。评估指标通常是$K$条预测轨迹下的最小平均位移误差：

$$\text{minADE}_K = \min_{k \in \{1, \ldots, K\}} \frac{1}{T} \sum_{t=1}^{T} \| \hat{\mathbf{p}}_t^{(k)} - \mathbf{p}_t \|_2$$

- 这是一种“最佳$K$项”评估方式：只要模型给出的$K$条预测结果中有任何一条接近真实值，该模型就能获得良好评价。这种机制有助于产生更多样化、多模式的预测结果。

- **社会力量模型**则将行人的行为视为一个动态系统，每个人都会受到朝向目标的吸引力，以及远离其他行人和障碍物的排斥力的作用。第$i$个人的加速度则为：

$$\mathbf{a}_i = \frac{\mathbf{v}_i^{\text{desired}} - \mathbf{v}_i}{\tau} + \sum_{j \neq i} \mathbf{f}_{ij}^{\text{repulsive}} + \sum_{\text{walls}} \mathbf{f}_{\text{wall}}$$

- 这是一种微分方程系统，与本章第2个文件中的机器人动力学方程类似。该模型结构简洁，但需要手动调整力参数，且难以处理复杂的多智能体交互场景。

- **图神经网络（GNN）**将场景视为图结构来构建预测模型：每个智能体对应一个节点，节点间的边则表示空间关系（如距离、车道共享关系）。节点间的信息传递能够捕捉各种交互情况，例如“这辆车正在为行人让路”或“这两辆车辆正并入同一车道”。

- 现代的预测架构（如**MTR**、**QCNet**）采用基于Transformer的模型，这类模型能够同时考虑智能体的历史行为、环境背景以及智能体之间的交互关系。通过交叉注意力机制，智能体可以关注相关的地图特征（当前所在车道、即将到来的交叉口），以及其他智能体（前方的车辆、人行横道上的行人）。最终输出的是通过自回归方式或混合模型生成的轨迹假设集。

- **目标条件驱动的预测**首先预测智能体可能前往的位置（即一组候选目标点，如车道终点或交叉口出口），然后再预测到达每个目标点的轨迹。这种方法将问题分解为“去往何处”（离散且易于处理）和“如何到达”（给定目标后的连续路径），从而使得多模态预测问题更易解决。

## 规划

- 在得到预测后的场景信息后，规划器需要为自身车辆生成一条轨迹。这是一个带约束的优化问题：需要找到一条既安全、又舒适、高效且符合规则的轨迹。

- **基于规则的规划器**将驾驶行为编码为一组“如果-那么”规则，例如：“如果人行横道上有行人，则需让行”、“如果与前车的距离小于2秒，则不得变道”、“如果接近红灯，则需减速并在停止线处停下”。这些规则易于理解且可被审核，但在面对复杂场景时就会显得不够实用——因为此时需要处理数千条规则、众多边缘情况以及规则之间的相互作用。

- **基于优化的规划器**则将驾驶问题转化为轨迹优化问题。自身车辆的轨迹会被参数化表示（例如，作为未来各个时间步的$(x, y, \theta, v)$状态序列），然后通过最小化某个目标函数来实现最优轨迹：

$$\min_{\boldsymbol{\xi}} \underbrace{w_1 \cdot J_{\text{progress}}(\boldsymbol{\xi})}_{\text{到达目的地}} + \underbrace{w_2 \cdot J_{\text{comfort}}(\boldsymbol{\xi})}_{\text{平稳行驶}} + \underbrace{w_3 \cdot J_{\text{safety}}(\boldsymbol{\xi})}_{\text{避免碰撞}}$$

$$\text{约束条件：运动学约束、速度限制、车道边界限制}$$

- “进度项”用于惩罚偏离预定路线的行为；“舒适性项”则用于惩罚过大的横向加速度、急加速/急减速现象，因为这些都会影响乘客的舒适度；“安全性项”则通过预测的轨迹来评估与其他智能体的接近程度，从而避免碰撞风险。

- 这属于带约束的优化问题（见第3章）：即在不等式约束条件下最小化成本函数。权重$w_1、w_2、w_3$用于权衡不同的目标——激进驾驶虽然能更快到达目的地，但会降低舒适性和安全性。

- **基于学习的规划器**则利用在人类驾驶数据上训练得到的神经网络来生成轨迹。该模型能够观察场景并直接输出规划好的轨迹，从而从专家级人类驾驶的实例中隐式地学习到各种复杂的权衡因素。

- 其优势在于能够全面捕捉人类驾驶行为，包括那些难以用形式化方法描述的细微之处，比如何时应该激进并线、在交叉口何时应轻推油门、应为骑自行车的人留出多少空间等。不过，它也存在与模仿学习相同的分布偏移问题（见第2个文件）：在训练数据中未充分覆盖的场景中，模型的表现可能会变得不可预测。

## 端到端驾驶

- **端到端驾驶**完全消除了各模块之间的界限。单个神经网络可以直接接收原始传感器输入（如摄像头图像、LiDAR点云数据），并直接输出驾驶指令（转向、油门、刹车控制）或规划好的轨迹。无需单独的感知、预测或规划模块。

- 这种方法的优点在于整个系统是针对最终目标（安全驾驶）而共同优化的，因此不会在模块之间丢失任何信息。感知模块会学会提取规划器所需的精确特征，而非那些可能无法反映任务相关细节的通用物体检测结果。

- **UniAD**（统一自动驾驶系统）是一种具有里程碑意义的端到端架构。它首先通过BEV编码器处理多摄像头图像，然后再依次应用一系列基于Transformer的模块，包括跟踪、在线地图构建、运动预测、占用区域预测以及规划功能。虽然它内部存在多个模块，但这些模块都是可微分的，且会一起进行端到端训练，规划过程中的损失函数会通过整个网络反向传播。

- UniAD中的规划模块会结合预测得到的BEV特征、其他智能体的轨迹以及占用区域信息，来生成未来车辆的位置点。这实际上就是第3章中提到的多变量链式法则的应用：规划过程中的损失梯度会一直传递回图像编码器，从而指导感知模块如何提供更有用的特征信息。

- 更新的端到端驾驶方法则采用类似VLA的架构（见本章第3个文件）。像**DriveVLM**这样的模型能够接收摄像头图像以及导航指令或路线信息，然后通过VLM架构来生成驾驶动作。这样一来，大规模预训练所带来的优势——如视觉理解能力和推理能力——就能直接应用于驾驶系统中。

- 端到端驾驶面临的挑战在于**可解释性**。模块化系统可以明确报告“我在(x, y)位置检测到了行人，并预测他们将会过马路”——这样的故障模式很容易诊断。而端到端系统则是一个黑箱，只会输出转向角度。一旦出现故障，就很难确定原因，这对安全认证来说是一个严重的问题。

## 驾驶用世界模型

- **世界模型**能够根据当前状态以及车辆自身的行为来预测驾驶场景的未来状态：$p(s_{t+1} \mid s_t, a_t)$（详见第10章）。在自动驾驶中，这意味着可以生成逼真的未来场景或BEV坐标系下的场景图像：“如果我加速并向左转向，3秒后场景就会变成这样。”

- 世界模型为自动驾驶提供了两项强大的功能：

- **基于想象的规划**：规划器无需先采取某种行动再观察结果，而是可以通过世界模型“想象”出多种可能的行驶路径，进而评估每种路径的安全性与舒适性，最终选择最优方案。这其实就是将基于模型的强化学习（详见本章的第2个文件）应用到了自动驾驶领域。

- **学习型仿真**：通过真实驾驶数据训练得到的世界模型实际上就是一个数据驱动的仿真器。它无需人工手动构建仿真环境，就能生成逼真的场景（包括那些罕见的极端情况）。更重要的是，它能捕捉到真实驾驶中的统计规律：其他驾驶员的实际行为方式、光线变化情况以及降雨对视野的影响。

- **GAIA-1**（Wayve）是一种用于自动驾驶的生成式世界模型。给定一系列过去的摄像头画面以及车辆的行为信息，它就能自回归地生成未来的视频画面。该模型采用了以动作信息为条件的视频扩散架构。通过训练，该模型能够生成合理的未来场景：遵守交通规则的车辆、在人行道上行走的行人，以及正常切换状态的交通信号灯——所有这些内容都是从训练数据中生成的，而非通过编程设定的规则。

- **DriveDreamer**和**GenAD**采用类似的方法，但它们是在BEV坐标系而非像素坐标系中进行运算的。预测BEV坐标系下的场景比生成完整的视频画面更为高效（这与机器人技术中的DreamerV3在潜在空间而非像素空间中进行预测的原理类似，详见第2个文件）。BEV世界模型能够预测所有车辆的位置、道路的结构以及空闲区域的位置，规划器可以直接利用这些信息来进行决策。

- **神经网络闭环仿真**则利用世界模型来替代手工构建的仿真器，从而进行测试。以真实的驾驶记录作为起点，世界模型可以模拟出如果车辆采取不同行动会出现的情景。这样一来就可以进行反事实分析：“如果我晚0.5秒刹车会怎样？”而无需实际重现该场景。

- 这里与**JEPA**框架（第10章）有着密切的联系。驾驶世界模型无需预测精确到每个像素的完美未来场景，只需预测对规划而言重要的信息：各车辆的位置、行驶速度以及空闲区域的位置。采用嵌入空间预测方法（即JEPA风格）可以捕捉到这些具有语义意义的属性，而不会在无关的视觉细节上浪费计算资源，比如云层的精确纹理。

- 最大的挑战在于**长时序预测的准确性**。世界模型会随着时间的推移不断积累误差：第2帧中的一个小错误就会影响到后续的所有帧。对于驾驶来说，3秒的预测时间范围足以用于做出战术性决策（比如现在是否应该并线？），但对于需要制定路线规划等战略性决策而言，30秒的预测时间仍然不够可靠。目前的研究通过重新校准模型（定期用真实数据重置模型）以及不确定性估计（在预测结果不可靠时发出警报）来缓解这一问题。

## 仿真

- 通过在真实道路上测试自动驾驶汽车固然必要，但还不够。危险场景（如险些发生碰撞的情况、极端情况）极为罕见，因此仅通过行驶里程来测试效率低下。要想从统计学角度证明汽车的安全性，它需要行驶数亿英里，这显然是不可行的。

- **仿真**则能提供无限量、可控制且安全的测试环境。那些在现实世界中很少出现的场景（如儿童突然冲到马路上、轮胎爆裂、突然出现障碍物等），在仿真环境中可以被重复测试数百万次。

- **CARLA**是一款基于Unreal Engine开发的开源驾驶仿真器。它能够提供逼真的城市环境、动态天气、交通参与者以及各种传感器模拟功能（如摄像头、激光雷达、雷达等）。研究人员利用CARLA来训练基于强化学习的驾驶系统，并评估感知算法的性能。

- **nuPlan**（Motional）则是一种闭环规划基准测试工具。与开环评估方式（回放记录的数据，然后将规划器的输出与人类驾驶员的实际行驶轨迹进行比较）不同，闭环评估允许规划器的决策直接影响仿真过程：如果规划器决定变道，仿真环境也会随之发生变化。这种方式能够测试系统的反应能力，而不仅仅是轨迹的相似度。

![开环评估只是回放记录的场景，不涉及模型行为的干预；闭环评估则允许模型行为改变仿真环境的状态](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/open_vs_closed_loop.svg)

- **开环评估**与**闭环评估**之间的区别非常重要：

- 开环评估：回放已记录的场景，计算模型输出与人类驾驶员行为的相似程度。这种方法虽然易于实现，但容易产生误导：一个总是预测“直行”的模型，在高速公路上可能误差很小，但在第一个转弯处就可能会引发事故。

- 闭环评估：模型做出的决策会改变仿真环境的状态，仿真环境也会随之发生变化。这种方式能够测试模型从自身错误中恢复过来并应对动态情况的能力。虽然成本更高，但意义要大得多。

- **场景生成**用于创建能够对系统施加压力的测试案例。通过优化算法，可以生成一些让自动驾驶系统表现最差的对抗性场景（如某辆车突然刹车、有行人躲在停着的汽车后面等）。这与机器学习中的对抗性训练（第6章）类似：寻找那些能最大化损失值的输入数据。

## 安全性

- 自动驾驶的安全性是由工程标准来保障的，而不仅仅是依赖机器学习指标。
- **ISO 26262**（功能安全标准）是针对那些对安全性要求极高的汽车电子系统的标准。该标准根据潜在危险的严重性、发生概率以及可控制性，将汽车安全完整性等级划分为从A级（最低）到D级（最高）的不同级别。自动驾驶系统中的感知与规划模块通常属于最高级别的D级，因此需要经过严格的验证，并采用冗余设计及故障安全机制。

- **SOTIF**（预期功能的安全性，ISO 21448标准）则着眼于另一类危险：并非硬件故障（这类问题由ISO 26262标准来规范），而是系统按设计正常工作却仍会导致危险情况出现的情况。例如，如果感知系统将白色卡车误判为天空，这就是SOTIF问题——硬件本身没有故障，但算法的缺陷却引发了危险。

- **运行设计域**规定了自动驾驶系统允许工作的条件：具体的地理区域、道路类型（仅高速公路、城市道路或两者皆有）、天气状况（无大雪）、行驶速度范围以及一天中的不同时间。系统不得在运行设计域之外工作；如果系统无法应对雪天条件，那就不应在雪天行驶。

- **故障安全设计**与**故障继续运行设计**的区别：
- 故障安全设计：一旦检测到故障，系统会立即进入安全状态（例如靠边停车）。这是最基本的要求。
- 故障继续运行设计：即便出现故障，系统也能依靠冗余组件继续安全运行。具备冗余转向、制动和计算功能的自动驾驶汽车，即便某个组件出现故障，依然能够继续行驶并到达安全地点。

- **冗余设计**至关重要。关键的感知传感器会被复制多份：多个摄像头覆盖相互重叠的视野范围，激光雷达和雷达分别提供独立的深度数据，还有两个运行相同软件的计算平台。这样一来，即使某个组件出现故障，其他组件仍能提供足够的信息以确保安全行驶。

## 自动驾驶等级

![SAE定义的自动驾驶等级，从L0（无自动化）到L5（完全自动化），显示了责任从人类转移到系统的过程](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/sae_autonomy_levels.svg)

- **SAE J3016**标准将驾驶自动化程度分为六个等级，从0级（无自动化）到5级（完全自动化）：

- **0级（无自动化）**：所有操作都由人类完成。系统可以发出警告（如车道偏离警报），但不会控制车辆。

- **1级（驾驶辅助）**：系统可以控制转向或车速，但不能同时控制两者。自适应巡航控制（保持车速和车距）或车道保持辅助功能都属于1级。

- **2级（部分自动化）**：系统可以同时控制转向和车速，但人类必须始终监控车辆状况，并随时准备接管控制权。特斯拉的Autopilot、通用汽车的Super Cruise以及目前大多数“自动驾驶”功能都属于2级。此时人类仍然是驾驶员。

- **3级（条件自动化）**：系统可以在特定条件下（即运行设计域内）负责驾驶并监测周围环境。人类可以暂时不干预，但必须在系统提出请求时及时接管控制权（通常有10秒左右的缓冲时间）。梅赛德斯的Drive Pilot就是首个获得认证的3级系统，它仅在某些高速公路上、时速低于60公里时可用。

- **4级（高度自动化）**：系统可以在其运行设计域内的所有情况下独立驾驶，无需人类干预。一旦遇到超出该区域的情况，系统能够自行安全停止。Waymo的无人出租车服务就在某些特定地区以4级水平运行。

- **5级（完全自动化）**：系统可以在任何条件下、在任何人类能够驾驶的道路上独立驾驶，甚至不需要方向盘和踏板。目前这一级别尚未实现。

- 最重要的区别在于**谁来承担安全责任**。在0级到2级中，责任在人类手中；而在3级到5级中，责任则在系统身上（当然是在其运行设计域内）。这一点具有重大的法律、保险和伦理意义。

- 目前，行业内普遍使用的是2级自动驾驶技术（已广泛应用），3级技术正在逐步推广，4级技术则仅在有限区域内应用。5级自动驾驶仍然是一个长期的研究目标。

1. 实现一个简单的轨迹优化规划器。给定起始位置、目标位置以及障碍物信息，利用梯度下降法找到一条最平滑且无碰撞的路径。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Trajectory: N waypoints, each (x, y)
N = 20
start = jnp.array([0.0, 0.0])
goal = jnp.array([10.0, 0.0])
obstacle = jnp.array([5.0, 0.0])
obs_radius = 1.5

# Initialise: straight line from start to goal
waypoints_init = jnp.linspace(start, goal, N)

def cost(waypoints):
    wp = jnp.concatenate([start[None], waypoints, goal[None]], axis=0)

    # Smoothness: penalise acceleration (second differences)
    accel = wp[2:] - 2 * wp[1:-1] + wp[:-2]
    smooth_cost = jnp.sum(accel ** 2)

    # Obstacle avoidance: penalise proximity
    dists = jnp.linalg.norm(wp - obstacle, axis=1)
    collision_cost = jnp.sum(jnp.maximum(0, obs_radius + 0.5 - dists) ** 2)

    return 10 * smooth_cost + 100 * collision_cost

grad_cost = jax.grad(cost)

# Optimise the interior waypoints
waypoints = waypoints_init[1:-1]
lr = 0.01
for _ in range(500):
    g = grad_cost(waypoints)
    waypoints = waypoints - lr * g

# Plot
full_path = jnp.concatenate([start[None], waypoints, goal[None]], axis=0)
theta = jnp.linspace(0, 2 * jnp.pi, 100)

plt.figure(figsize=(10, 4))
plt.plot(full_path[:, 0], full_path[:, 1], "b.-", label="Optimised path")
plt.plot(waypoints_init[:, 0], waypoints_init[:, 1], "r--", alpha=0.5, label="Initial (straight)")
plt.fill(obstacle[0] + obs_radius * jnp.cos(theta),
         obstacle[1] + obs_radius * jnp.sin(theta), alpha=0.3, color="red", label="Obstacle")
plt.plot(*start, "go", markersize=10); plt.plot(*goal, "g*", markersize=15)
plt.legend(); plt.axis("equal"); plt.grid(True)
plt.title("Trajectory Optimisation: Smooth Collision-Free Path")
plt.show()
```

```python
import jax.numpy as jnp
import matplotlib.pyplot as plt

# Ground truth: vehicle turning right
dt = 0.1
T = 40  # 4 seconds
v = 10.0  # m/s
omega = 0.3  # rad/s (turning rate)

# True trajectory (constant turn rate)
t = jnp.arange(T) * dt
theta = omega * t
gt_x = (v / omega) * jnp.sin(theta)
gt_y = (v / omega) * (1 - jnp.cos(theta))

# Constant velocity prediction from t=0
# Assumes the car continues straight at its current heading
obs_steps = 10  # observe first 1 second
vx0 = v * jnp.cos(theta[obs_steps - 1])
vy0 = v * jnp.sin(theta[obs_steps - 1])
pred_t = jnp.arange(T - obs_steps) * dt
pred_x = gt_x[obs_steps - 1] + vx0 * pred_t
pred_y = gt_y[obs_steps - 1] + vy0 * pred_t

plt.figure(figsize=(8, 6))
plt.plot(gt_x[:obs_steps], gt_y[:obs_steps], "ko-", label="Observed")
plt.plot(gt_x[obs_steps:], gt_y[obs_steps:], "g-", linewidth=2, label="True future")
```

1. 实现一个基于规则的简单规划器，根据检测到的障碍物来决定是保持车道行驶还是停车。

```python
import jax.numpy as jnp

def rule_based_planner(ego_speed, obstacles, speed_limit=13.9):
    """
    Simple rule-based planner.
    ego_speed: current speed (m/s)
    obstacles: list of (distance, speed) tuples for vehicles ahead
    speed_limit: max allowed speed (m/s), default ~50 km/h

    Returns: (target_speed, action_label)
    """
    min_following_distance = 2.0 * ego_speed  # 2-second rule
    emergency_distance = 5.0  # metres

    if not obstacles:
        return speed_limit, "cruise"

    # Find closest obstacle ahead
    closest_dist, closest_speed = min(obstacles, key=lambda o: o[0])

    if closest_dist < emergency_distance:
        return 0.0, "EMERGENCY STOP"
    elif closest_dist < min_following_distance:
        # Match speed of vehicle ahead
        target = min(closest_speed, speed_limit)
        return target, "following"
    else:
        return speed_limit, "cruise"

# Test scenarios
scenarios = [
    (13.9, [], "Empty road"),
    (13.9, [(30.0, 10.0)], "Slower car ahead"),
    (13.9, [(3.0, 0.0)], "Stopped car very close"),
    (13.9, [(50.0, 13.9)], "Car ahead at same speed"),
]

for speed, obs, desc in scenarios:
    target, action = rule_based_planner(speed, obs)
    print(f"{desc:30s}  →  {action:15s} target_speed={target:.1f} m/s ({target*3.6:.0f} km/h)")
```

## 太空与极端环境机器人技术

_在太空及极端环境中，机器人需要具备极高的自主性——因为通信延迟、辐射以及复杂的地形都要求机器人能够独立决策。本章将探讨行星探测器、轨道维修机器人、受通信限制条件影响的自主系统、抗辐射计算技术、水下机器人、搜救机器人、群体机器人以及人机交互技术。_

- 在前面的章节中，我们研究的是在相对理想的环境中运行的自主系统：有车道标记的道路、地面平坦的仓库、物品种类明确的厨房。然而，机器人技术一些最具影响力的应用场景，却是那些人类无法进入或进入成本极高的地方：火星表面、深海海底、核灾难现场以及正在燃烧的建筑物。

- 这些**极端环境**面临着共同的挑战：通信受到限制或存在延迟，地形复杂且难以预测，硬件必须能够在恶劣条件下正常工作，而且当出现问题时也没有人类可以在附近进行修复。因此，机器人必须真正实现自主运行，而不仅仅是“有人监控下的自主运行”。

## 太空机器人技术

- 太空堪称最极端的生存环境。那里没有空气，温度在-170°C到+120°C之间波动，辐射会破坏电子设备，而且救援力量距离数百万公里之远。因此，太空机器人必须具有极高的可靠性、能效以及自主性。

- **行星探测器**是一种用于探索其他星球表面的移动机器人。NASA的火星探测器（如“勇气号”、“机遇号”、“好奇号”和“毅力号”）就是最著名的例子。每一代探测器都比前一代更具自主性。

![地球与火星之间的通信延迟：单程需4-24分钟，往返则需8-48分钟，因此无法实现实时控制](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/earth_mars_delay.svg)

- 最根本的制约因素就是**通信延迟**。根据轨道位置的不同，从地球到火星的无线电信号传输时间在4到24分钟之间，因此往返通信所需时间为8到48分钟。这意味着无法通过遥控方式实时操控探测器。如果探测器遇到障碍物，它无法向地球请求帮助并等待回复，而必须自行做出决策。

- 早期的探测器（如“勇气号”和“机遇号”）依赖地面控制的规划方式：人类先分析图像、规划路径、上传指令，然后由探测器执行这些指令。一个完整的行驶周期相当于一个火星日的时间，探测器每天的行进距离大约在50到100米左右。

- “好奇号”和“毅力号”所采用的**自动导航系统**大大提升了它们的自主性。这些探测器利用立体相机构建局部3D地图（可参考第8章关于立体深度的内容），评估地形的通行性（如坡度、粗糙度、岩石大小），并通过基于网格的规划算法来选择安全的行驶路径。这样，即使在人类团队休息时，探测器也能自主行驶，每天的行进距离可达到100米以上。

- 火星探测器的感知系统受到抗辐射处理器的限制，这类处理器的运算速度远远低于普通消费级硬件（详见下文）。因此，所使用的算法必须尽可能节省计算资源：采用传统的立体匹配技术而非深度神经网络，使用简单的成本地图规划算法而非基于学习模型的策略。

- **轨道维修**是指在轨道上对卫星进行检测、维修、加注燃料或使其脱离轨道的任务。随着太空空间日益拥挤，这一领域的发展势头越来越强劲。像NASA的**OSAM-1**任务以及Astroscale、Northrop Grumman MEV等商业公司推出的产品，都利用机械臂和对接装置来为卫星提供服务。

- 这类任务面临的主要挑战是**近距离操作**：执行维修任务的航天器必须接近目标卫星（而目标卫星可能处于旋转状态、无法配合操作，且没有对接接口），并在微重力环境下进行精确的操作。基于视觉的姿态估计技术至关重要——即通过相机图像确定目标卫星的3D位置和方向。这项技术运用了第8章中介绍的各种方法，如特征检测、PnP算法，以及最新的基于深度学习的姿态估计技术。

- **卫星检测**则是利用小型航天器对其他卫星进行目视检查，以发现其上的损坏或异常情况。执行检测任务的航天器必须能够自主地在目标卫星周围移动，避免碰撞，并从最佳角度获取高分辨率图像。这实际上是一个规划问题：需要在满足燃料限制、光照条件以及避免碰撞的前提下，找到能够覆盖所有检测点的最优路径。

## 通信限制

- 在太空中，通信受到光速、可用带宽以及轨道几何条件的限制。位于火星背面的探测器如果没有中继卫星的话，就根本无法与地球通信。

- 这些限制从根本上改变了机器人的自主性设计。在地球上，机器人可以将高清视频传输到云端服务器，利用GPU集群进行处理，同时也能在几毫秒内收到指令。而在太空中，机器人必须所有操作都在自身内部完成。

- **高延迟**意味着机器人必须在没有实时人类指导的情况下进行规划和行动。自主性软件必须能够处理常规操作、检测异常情况，并在面对危险时立即作出反应，而无需等待人类的指令。这就要求机器人具备强大的本地状态估计能力、故障检测功能以及应急规划能力。

- **有限的带宽**意味着机器人无法传输原始的传感器数据。一张高分辨率图像的体积可能高达数兆字节，但通过直接连接地球的链路，火星向地球发送数据的速率仅为几千比特/秒；即便通过轨道中继，速率也仍然有限。因此，机器人必须对数据进行高效压缩，决定哪些数据需要发送，而且大多数决策都需要在本地完成。

- **通信窗口**是间歇性的。火星探测器只有在特定的轨道条件下才能与地球通信，通常通过中继卫星，每次通信时间仅为几个小时。在这段时间内之外，探测器完全只能依靠自身能力行事。
- 对人工智能而言，这意味着**机器人的自主性**必须具备极高的可靠性。系统需要能够检测出是否存在问题（如车轮卡住、传感器故障、前方地形无法通行等），并决定安全的应对措施，然后继续运行，直到下一个通信窗口到来时再上报情况并接收新的指令。

## 抗辐射计算技术

- 太空环境中充斥着各种电离辐射：宇宙射线、太阳粒子爆发，以及行星磁场中存在的辐射。高能粒子可能会改变内存中的数据状态（即“单事件干扰”），或永久性地损坏晶体管，甚至导致电路出现故障。

- **抗辐射处理器**就是为应对这种环境而设计的。它们采用更大的晶体管结构、冗余逻辑设计（每种电路都有三个副本，共同决定输出结果），以及特殊的制造工艺。不过，性能与成本之间存在 trade-off：最先进的抗辐射处理器的运算速度约为200 MIPS，而普通消费级GPU的运算速度则可达数十亿次/秒。

- “RAD750”处理器由BAE Systems公司生产，曾被用于“好奇号”探测器以及许多其他航天器上。它的运行频率为200 MHz，运算能力约为400 MIPS，这一性能水平相当于20世纪90年代中期的台式电脑。 “毅力号”探测器也使用了类似类型的处理器。在这样的硬件上运行现代神经网络（拥有数百万个参数，需要执行数十亿次乘法-累加操作）是不可能的。

- 因此，**模型压缩**变得十分重要。第6章中介绍的各种技术——如量化、剪枝、知识蒸馏等——被用来缩小神经网络的规模，使其能够在有限的计算资源下运行。在笔记本电脑的GPU上只需几毫秒就能运行的模型，在抗辐射处理器上可能需要几分钟才能运行，甚至可能因为体积过大而无法放入内存中。

- 另一种方法是使用经过软件层面抗辐射处理的**商用现成处理器**：通过纠错码、看门狗定时器、定期清除内存数据等功能来降低辐射带来的影响。一些现代航天任务采用这种方法来获得更强的计算能力，但相应的软件复杂度也会增加，风险也会随之上升。

- 未来的行星探测任务正在探索**FPGA**以及专门的AI加速器，这类器件不仅具有抗辐射能力，还能提供比传统抗辐射CPU更高的计算性能，这有望首次实现航天器上的深度学习应用。

## 在无结构地形中的自主导航

- 在地球上，道路是平坦的、有明确标识且已被详细测绘的。而在火星、月球或灾难发生地，则不存在道路。这些地形往往毫无规律可循：到处都是岩石、斜坡、沙子、裂缝，还有可能无法承受机器人重量的表面。

- **地形分类**的作用是判断每块地面是否适合机器人通行。评估因素包括坡度（通过3D重建得出）、表面粗糙度（表面法向量的变化程度）、岩石密度以及土壤类型。传统方法是通过立体深度图来计算这些参数；而现代方法则利用基于视觉和几何特征的机器学习模型来进行判断。

- **视觉-惯性定位技术**通过跟踪不同相机帧中的视觉特征，并结合惯性测量单元的数据，来估算机器人的运动状态。这是SLAM技术的重要组成部分（见第8章），经过改进后可用于极端环境。在火星上，这种技术还需要应对没有明显视觉特征的沙地、极端的照明条件以及有限的计算资源。

- 该技术的核心是运用**扩展卡尔曼滤波器**或因子图优化方法，将视觉数据和惯性数据结合起来进行分析。状态向量包括位置、速度、方向以及惯性测量单元的偏差值。预测阶段则利用惯性测量单元的数据来进行计算：

$$\mathbf{x}_{t+1} = f(\mathbf{x}_t, \mathbf{u}_t)$$

其中，$\mathbf{u}_t$表示惯性测量单元检测到的加速度和角速度。更新阶段则根据视觉特征的数据来修正预测结果。这实际上是一种贝叶斯估计方法（见第5章）：惯性测量单元提供初始估计值，而视觉观测数据则用于更新这一估计值。

- 在行星着陆过程中，**避免危险**至关重要。当航天器向地表下降时，它必须利用机载摄像头或激光雷达实时识别出安全的着陆区域。NASA的“毅力号”探测器就采用了“地形相对导航系统”，该系统通过比较机载摄像头拍摄的图像与预先加载的轨道地图，来确定探测器的位置，从而避开危险地形。这一技术使得“毅力号”能够在杰泽罗陨石坑着陆，而这个地方虽然科学价值极高，但地形极为复杂，之前的探测器根本不敢尝试着陆于此。

## 水下机器人技术

- 深海环境与太空环境一样充满挑战：巨大的压力（海洋最深处的气压可达1000多个大气压）、几乎为零的能见度、没有GPS信号，而且通信条件也非常有限。水下机器人对于海洋科学研究、海上基础设施检查、深海采矿以及搜救任务来说不可或缺。

- **自主水下航行器**无需缆绳连接，自带能源和计算设备。它们可以按照预编程的路线进行作业，或者依靠自身的智能系统来适应不同的环境状况。这类机器人被用于海底测绘、管道检查以及环境监测等工作。

- **遥控水下机器人**则通过电缆与水面上的船只相连，电缆既为机器人提供能源，也负责数据传输。它们适用于那些需要人类实时控制的任务，比如在深海中进行操作、建造或维修工作。虽然电缆消除了通信限制，但却限制了机器人的活动范围，并增加了操作复杂性。

- **声波通信**是水下主要的通信方式（无线电波在水中传播速度很慢）。声波调制解调器的传输速率仅为1-10 kbps，通信距离也只有几公里，而陆地上的无线电通信速率则可达千兆比特/秒。相比火星上的通信条件，水下通信的局限性更大，因此自主水下航行器必须具备高度的自主性。
- **水下SLAM**技术面临极大挑战。声纳虽能提供距离测量数据，但角度分辨率较低，且存在大量噪声（来自海底和海面的多路径反射）。摄像头则只能在极近的距离内使用（在清澈的水中为几米，而在浑浊的水中则更短）。基于特征的视觉SLAM技术（第8章）需要针对水下场景的独特视觉特性进行调整：颜色衰减（红光会被首先吸收）、后向散射，以及人造光源带来的亮斑和深色阴影。

- 在没有GPS的情况下，导航依靠的是**惯性测量**（通过多普勒速度记录仪获取相对于海底的速度信息），同时会偶尔浮出水面以利用GPS定位或通过水面应答器进行定位。这与仅依赖IMU的导航方式存在同样的问题：在长时间任务中，微小的速度误差会不断累积。

## 搜救机器人

- 地震、建筑物倒塌或工业事故发生后，机器人可以进入对人类救援人员来说过于危险的区域：结构不稳定的建筑、有毒环境、火灾现场或密闭空间。

- 这类应用的要求包括：快速部署（几分钟内即可投入使用，而非数小时）、在无GPS信号的环境中工作（如建筑物内部、地下）、能够穿透墙壁和废墟实现稳定通信，以及能够在充满杂物、灰尘且照明条件恶劣的空间中导航。

- **多机器人协作**在搜救工作中非常重要，因为多个机器人共同作业可以比单个机器人更快地覆盖更大范围。不过，协调工作是个难题：各机器人需合理划分搜索区域，避免重复劳动，并共享发现的信息。

- **边界探索策略**则是将机器人部署在已探索区域与未探索区域之间的边界上。每个机器人都会前往最近的未探索区域进行测绘，然后再继续前进。中央控制器或分布式规划器会负责为机器人分配任务，从而最小化整体探索时间。这实际上是一个覆盖优化问题。

- 通过废墟进行通信是不可靠的。机器人可能会与操作员及其他机器人失去联系。因此，系统必须具备应对间歇性通信中断的能力：每个机器人都应能够独立工作，自行构建本地地图并做出决策，待通信恢复后再整合信息。

## 群体机器人

- **群体机器人**技术利用大量简单、低成本的机器人，通过它们之间的局部互动来实现复杂的集体行为。虽然单个机器人无法独立完成某些任务，但整个群体却能完成单个机器人无法实现的任务。

- 这一技术的灵感来源于生物界的群体行为：蚂蚁用身体建造桥梁，蜜蜂共同决定筑巢地点，鱼群通过协同行动躲避捕食者。在每种情况下，简单的局部规则（跟随邻居、避免碰撞、朝向食物移动）就能产生复杂的整体行为。

- **去中心化控制**意味着不存在统一的指挥者。每个机器人都遵循相同的局部规则，只对周围的邻居及当前环境作出反应。整体的群体行为正是由这些局部互动产生的。这也使得群体机器人具有很强的稳定性：即使某个机器人出现故障，整个群体仍能继续工作，不存在单一的故障点。

- **共识算法**允许群体仅通过局部通信就能就集体决策达成一致（例如决定移动方向或优先处理哪项任务）。一种简单的共识协议是让每个机器人将自己的数值与邻居的数值相平均：

$$x_i(t+1) = \frac{1}{|N_i| + 1} \left( x_i(t) + \sum_{j \in N_i} x_j(t) \right)$$

![群体共识机制：机器人最初分散分布，通过与邻居的数值平均逐步趋同到同一位置](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/swarm_consensus.svg)

其中$N_i$表示机器人$i$的邻居集合。这一过程会不断重复，直到所有机器人都达到相同的数值（即全局平均值）。收敛速度取决于通信图的拓扑结构，尤其是其代数连通性（即图拉普拉斯矩阵的第二小特征值，相关内容见第2章）。

![雷诺兹的三种群集规则：分离规则避免碰撞，对齐规则使机器人保持相同方向，凝聚规则让机器人留在群体中](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/reynolds_flocking.svg)

- **群集算法**（基于雷诺兹规则）通过每台机器人遵循的三个简单规则来实现群体的协同运动：
- **分离规则**：避开距离过近的邻居，以避免碰撞。
- **对齐规则**：朝邻居的平均行进方向移动，从而保持相同方向。
- **凝聚规则**：朝邻居的平均位置移动，从而保持在群体中。

- 每条规则都会为机器人的速度贡献一个向量值。这些向量值的加权求和便形成了自然的群集行为。这实际上是一种向量的线性组合（见第1章），其中的权重决定了各种行为的相对重要性。

- 群体机器人的应用领域包括环境监测（在广阔区域内部署传感器）、精准农业（协调无人机进行作物喷洒）、建筑施工（机器人共同组装建筑结构），以及搜救行动（高效覆盖大面积区域）。

## 人机交互

- 大多数现实世界的自主系统都是在与人类共同工作的环境中运行，而非孤立存在。人类与机器人之间的互动、他们之间的沟通方式、如何共享控制权以及如何建立信任，这些因素与机器人的技术性能同样重要。

![共享自主性谱系：从完全由人类操控（alpha=1），经过混合控制，到完全由机器人自主控制（alpha=0）](https://henryndubuaku.github.io/maths-cs-ai-compendium/images/shared_autonomy_spectrum.svg)

- **共享自主性**结合了人类与机器人的控制方式。与完全由人类控制的遥控操作或完全由机器人自主控制的模式不同，共享自主性允许人类设定高层次的指令，而机器人则负责执行具体的操作。例如，人类可以指向某个物体并说“把那个拿起来”，机器人则会自主规划抓取动作及手臂的运动。

- 从数学上讲，共享自主性可以被看作是人类输入$\mathbf{u}_h$与机器人自主行为$\mathbf{u}_r$的混合：

$$\mathbf{u} = \alpha \mathbf{u}_h + (1 - \alpha) \mathbf{u}_r$$

其中，$\alpha \in [0, 1]$为混合参数。当$\alpha = 1$时，人类拥有完全控制权；当$\alpha = 0$时，机器人则完全自主运行。自适应共享自主性会根据实际情况调整$\alpha$值：在机器人有足够把握时它会承担更多控制任务，而在情况不确定或面临新挑战时则会让渡控制权。

- 对于那些超出当前机器人自主能力范围的任务来说，遥控操作仍然非常重要。操作者可以通过机器人的摄像头远程控制机器人，并观察现场情况。不过，**延迟问题**是个难题：哪怕只有100毫秒的延迟也会让遥控操作变得困难，而在太空环境中数秒级的延迟则几乎使得精确操作成为不可能。为此，人们采用了预测显示功能（展示机器人未来的预期状态）以及虚拟辅助装置（通过软件引导来防止操作者发出可能带来危险的指令），以此来弥补这一缺陷。

- **信任度调节**是指如何让人类对机器人保持适当的信任度：既不能过度信任（过度信任会导致人们掉以轻心，从而在需要时未能及时干预），也不能缺乏信任（缺乏信任则会导致不必要的干预，进而无法充分利用机器人的能力）。信任度应根据机器人的实际能力来调整：在机器人能够妥善处理某些任务时给予信任，而在其能力边界附近的情况下则应保持谨慎。

- 研究表明，影响信任度的因素包括：机器人的透明度（它是否会解释自己的决策？）、可靠性（它的故障是可预测的还是随机的？）以及沟通能力（它能否表达出自身的不确定性？）。那种会说出“我对此路径的安全性有40%的把握，是否继续前进？”的机器人，比那些默默前行的机器人更能帮助人类做出更好的决策。

- 机器人动作的**可理解性**意味着机器人应以能够让周围人类明白其意图的方式移动。如果机器人要去拿某个物体，那么在它到达之前，其移动路径就应该能让人清楚地知道它目标是什么。这需要规划出这样的轨迹：尽可能让观察者能够尽早推断出机器人的目标，这一目标可以用给定部分轨迹后，真实目标的后验概率最大化来表示：

$$\pi^* = \arg\max_\pi P(G \mid \xi_{0:t})$$

其中，$G$代表目标，$\xi_{0:t}$则是目前已观察到的轨迹。这里运用了贝叶斯推理方法（见第5章）：观察者对可能的目标有先验判断，而机器人的轨迹则为更新这一判断提供了依据。

1. 模拟一群机器人共同确定目标位置的共识算法。首先给这些机器人设置随机初始位置，然后观察它们如何逐渐达成一致。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

n_robots = 10
rng = jax.random.PRNGKey(0)
positions = jax.random.uniform(rng, (n_robots, 2), minval=-5, maxval=5)

# Communication graph: each robot talks to its 3 nearest neighbours
def get_neighbours(positions, k=3):
    dists = jnp.linalg.norm(positions[:, None] - positions[None, :], axis=-1)
    # For each robot, find k nearest (excluding self)
    neighbours = jnp.argsort(dists, axis=1)[:, 1:k+1]
    return neighbours

history = [positions.copy()]

for step in range(30):
    neighbours = get_neighbours(positions)
    new_positions = jnp.zeros_like(positions)
    for i in range(n_robots):
        nbr_pos = positions[neighbours[i]]
        new_positions = new_positions.at[i].set(
            (positions[i] + nbr_pos.sum(axis=0)) / (len(neighbours[i]) + 1)
        )
    positions = new_positions
    history.append(positions.copy())

# Plot convergence
fig, axes = plt.subplots(1, 3, figsize=(15, 4))
for ax, step_idx, title in zip(axes, [0, 10, 29], ["Initial", "Step 10", "Final"]):
    h = history[step_idx]
    ax.scatter(h[:, 0], h[:, 1], s=50)
    ax.set_xlim(-6, 6); ax.set_ylim(-6, 6)
    ax.set_aspect("equal"); ax.grid(True); ax.set_title(title)
plt.suptitle("Swarm Consensus: Robots Converge to Agreement")
plt.tight_layout()
plt.show()
```

1. 实现雷诺斯的群集行为规则（分离、对齐、凝聚），并模拟一群机器人协同移动的场景。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

n = 30
rng = jax.random.PRNGKey(1)
k1, k2 = jax.random.split(rng)
pos = jax.random.uniform(k1, (n, 2), minval=-5, maxval=5)
vel = jax.random.uniform(k2, (n, 2), minval=-0.5, maxval=0.5)

dt = 0.1
separation_radius = 1.0
neighbour_radius = 3.0

trajectories = [pos.copy()]

for _ in range(200):
    new_vel = jnp.zeros_like(vel)
    for i in range(n):
        diffs = pos - pos[i]
        dists = jnp.linalg.norm(diffs, axis=1)

        # Neighbours within radius (exclude self)
        nbr_mask = (dists < neighbour_radius) & (dists > 0)
        sep_mask = (dists < separation_radius) & (dists > 0)

        # Separation: steer away from very close neighbours
        if sep_mask.any():
            sep = -diffs[sep_mask].sum(axis=0)
        else:
            sep = jnp.zeros(2)

        # Alignment: match average velocity of neighbours
        if nbr_mask.any():
            align = vel[nbr_mask].mean(axis=0) - vel[i]
        else:
            align = jnp.zeros(2)

        # Cohesion: steer toward average position of neighbours
        if nbr_mask.any():
            cohesion = pos[nbr_mask].mean(axis=0) - pos[i]
        else:
            cohesion = jnp.zeros(2)

        new_vel = new_vel.at[i].set(vel[i] + 1.5 * sep + 0.5 * align + 0.3 * cohesion)

    # Limit speed
    speeds = jnp.linalg.norm(new_vel, axis=1, keepdims=True)
    vel = jnp.where(speeds > 2.0, new_vel / speeds * 2.0, new_vel)
    pos = pos + vel * dt
    trajectories.append(pos.copy())

# Plot snapshots
fig, axes = plt.subplots(1, 3, figsize=(15, 4))
for ax, idx, title in zip(axes, [0, 50, 199], ["Start", "Step 50", "Step 200"]):
    p = trajectories[idx]
    v = vel if idx == 199 else jnp.zeros_like(vel)
    ax.scatter(p[:, 0], p[:, 1], s=20, c="blue")
    ax.set_aspect("equal"); ax.grid(True); ax.set_title(title)
    lim = max(abs(p).max() + 1, 6)
    ax.set_xlim(-lim, lim); ax.set_ylim(-lim, lim)
plt.suptitle("Reynolds' Flocking: Separation + Alignment + Cohesion")
plt.tight_layout()
plt.show()
```

1. 模拟自主性协同工作机制：人类给出有噪声的方向指令，而机器人的自主系统则负责规划通往目标的平滑路径。通过不同的α值来实现这两种机制的融合。

```python
import jax
import jax.numpy as jnp
import matplotlib.pyplot as plt

goal = jnp.array([10.0, 5.0])
pos = jnp.array([0.0, 0.0])
dt = 0.1

rng = jax.random.PRNGKey(3)

fig, axes = plt.subplots(1, 3, figsize=(15, 4))
for ax, alpha in zip(axes, [1.0, 0.5, 0.0]):
    pos = jnp.array([0.0, 0.0])
    path = [pos.copy()]

    for step in range(150):
        # Robot autonomy: smooth path to goal
        direction = goal - pos
        u_robot = direction / (jnp.linalg.norm(direction) + 1e-6) * 1.0

        # Human input: roughly correct direction but noisy
        noise = jax.random.normal(jax.random.fold_in(rng, step), (2,)) * 0.5
        u_human = u_robot + noise

        # Blend
        u = alpha * u_human + (1 - alpha) * u_robot
        pos = pos + u * dt
        path.append(pos.copy())

        if jnp.linalg.norm(pos - goal) < 0.3:
            break

    path = jnp.stack(path)
    ax.plot(path[:, 0], path[:, 1], "b-", alpha=0.7)
    ax.plot(*goal, "r*", markersize=15)
    ax.plot(0, 0, "go", markersize=10)
    ax.set_title(f"α={alpha:.1f} ({'human' if alpha==1 else 'robot' if alpha==0 else 'shared'})")
    ax.set_xlim(-1, 12); ax.set_ylim(-3, 8)
    ax.set_aspect("equal"); ax.grid(True)

plt.suptitle("Shared Autonomy: Blending Human and Robot Control")
plt.tight_layout()
plt.show()
```
